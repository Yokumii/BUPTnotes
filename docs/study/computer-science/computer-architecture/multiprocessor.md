# 多处理机

## 基本概念

- **多处理机**：具有多个 CPU 的计算机系统；
- 并行计算机系统结构的分类：
    - 按照**存储器**的组织结构，把 MIMD 分为
        - **集中式共享存储器**；
            - 最多几十个处理器，各处理器共享一个集中式的物理存储器。
            - 也被称为**对称共享存储器多处理机（SMP）**；
            - 这种结构被称为 UMA（Uniform Memory Access）结构，即各处理器访问存储器所花时间相同；
            - 目前**主流**。
            <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260620105544584.png){ loading=lazy width="70%" } </figure>
        - **分布式存储器**；
            - 存储器在物理上是分布的
            <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260620105624208.png){ loading=lazy width="70%" } </figure>
            - 优点：
                - 如果大多数访问是针对本结点的局部存储器，可以降低对存储器和互连网络的带宽需求
                - 对本地存储器的访问延迟较小
            - 缺点：
                - 处理器之间通信复杂
                - 处理机间访问延迟较大
- 分布式存储器多处理机两种存储器系统结构：
    - **共享全局地址空间**：
        - 物理上分离的所有存储器作为一个统一的共享逻辑空间进行编址
        - 分布式共享存储器系统 DSM（Distributed Shared Memory）/ **NUMA 机器（Non-Uniform Memory Access，非统一内存访问）**
            - Non-Uniform Memory Access（NUMA）是指在多处理器系统中，处理器访问不同的内存位置所需的时间不同。而不是不同的逻辑空间
        - 任何一个处理器可访问该共享空间的任意单元
        - 通信机制：**共享存储器通信机制**（load / store），优点：
            - 与集中式多处理机通信机制兼容
            - 易于编程
            - 采用大家所熟悉的共享存储器模型开发应用程序，把重点放到解决对性能影响较大的数据访问上
            - 通信数据量较小时通信开销较低，带宽利用较好
            - 可采用 Cache 减少远程通信频度，减少通信延迟和共享数据的访问冲突
        - 在共享存储器上支持消息传递相对简单
    - **分布式独立地址空间**：
        - 整个系统的地址空间由多个独立的地址空间构成
        - 每个结点只能访问本地存储器
        - 每个处理器-存储器模块实际上是一个单独的计算机
        - 通信机制：**消息传递通信机制**，优点：
            - 硬件简单
            - 通信是显式的
            - 显式通信可以让编程者重点注意并行计算的主要通信开销，使之有可能开发出结构更好、性能更高的并行程序
            - 同步很自然地与发送消息相关联，能减少不当的同步带来错误的可能性
        - 在分布式存储器上支持共享存储器困难得多

## 对称式共享存储器系统结构（SMP/UMA）

* 多个处理器共享一个存储器
* 支持共享数据进入 Cache $\rightarrow$ Cache 一致性问题
    * 多个处理器的 Cache 中都有同一存储块的副本，其中某个处理器对其 Cache 中的数据进行修改后，就会使得其 Cache 中的数据与其他 Cache 中的数据不一致。

### Cache 一致性问题

* **存储器一致性**：如果对某个数据项的任何读操作均可得到其最新写入的值，则认为这个存储器系统是一致的。若满足以下提交，则存储系统是一致的：
    1. P写后P读，中间没有其他处理器对该数据项进行写操作；
    2. P写后Q读，中间没有其他处理器对该数据项进行写操作；
    3. P写后Q写，**写串行化**（即任意两个处理器对同一单元的两次写，从各个处理器的角度看来顺序都是相同的）

假设：

* 直到所有的处理器均看到了写的结果，这个写操作才算完成；
* 允许处理器对读进行重排序，但必须以程序规定的顺序进行写。

Cache 一致性协议：关键在于跟踪记录共享数据块的状态，包括：

* 目录式协议：每个 Cache 的共享状态被保存在一个称为目录的地方
* 监听式协议：每个 Cache 保留共享状态的副本，通过广播和监听来实现一致性
    * Cache 包含物理存储器中数据块的拷贝，保存各个块的共享状态信息。
    * Cache 通常连在共享存储器的总线上。
    * 当某个 Cache 需要访问时，它把请求放到总线上广播出去。
    * 其他 Cache 控制器监听总线，判断它们自身是否有请求的数据块。如果有就进行相应操作。

2 种写更新操作：

* **写作废协议**：在处理器对某个数据项进行写入之前，保证它拥有对该数据项的唯一的访问权。(作废其它的副本)，应用广泛，对于监听或者目录方式皆可用。
* **写更新协议**：当处理器对某个数据项进行写入时，通过广播更新其它副本中的数据项的值。

??? info "单选题"
    总线监听协议在本地Cache的数据块被修改时，通过总线把改写的数据块广播到有该数据块的所有远程Cache中，这是监听协议的（   ）。

    A.写通过策略 B.写回策略 C.写无效策略 D.写更新策略

    答案：D

Cache 更新后对存储器写策略：

* 写直达 Cache：执行“写”操作时，不仅写入Cache，而且也写入下一级存储器。
    - 因为所有写入的数据都同时被写回主存，所以从主存中总可以取到其最新值。
* 写回 Cache：执行“写”操作时，只写入 Cache，直到该数据块被替换出 Cache 时才写回主存（设置修改位）。
    - 得到数据的最新值会困难一些，因为最新值可能在某个 Cache 中，也可能在主存中。

写更新 vs. 写作废性能：

* 对同一个数据进行多次写操作而中间无读操作时，写更新需要多次广播写操作，写作废只需要一次作废操作；
* 对统一 Cache 块的多个字进行写操作时，写更新对于每个字都需要广播写操作，而写作废只需在该块第一次写操作进行一次作废操作；
    * **写作废是针对 Cache 块进行操作**，而**写更新则是针对字（或字节）进行**。
* 考虑从一个处理器A进行写操作后到另一个处理器B能读到该写入数据之间的延迟时间。写更新协议的延迟时间较小，而写作废协议则需重新调入 Cache。
* 在基于总线的多处理机中，总线和存储器带宽是紧缺资源，写作废协议耗费带宽少，故多采用**写作废协议**。

### 监听协议的实现

* 在每个结点内嵌入一个有限状态控制器，每个数据块的状态包括：
    * **无效（I, Invalid）**：该数据块无效；
    * **共享（S, Shared）**：该数据块在一个或多个 Cache 中有副本，这些副本都相同且与存储器中的数据块一致；
    * **已修改（M, Modified）**：该数据块在一个 Cache 中有一个副本已经被修改还没有写回主存，且是唯一最新的副本。
* 处理器之间通过一个可以实现广播的互连机制相连，通常采用**总线**
* 当一个处理器的 Cache 响应本地 CPU 访问时，如果它涉及全局操作， 其 Cache 控制器就要在获得总线控制权后，在总线上发出相应消息。
* 所有处理器一直在监听总线，检测总线上的地址在否与它们的 Cache 中的数据块地址匹配，如果匹配就进行相应的操作。
* 写操作的串行化通过总线实现，按照获取总线控制权的顺序进行。

Cache 发出的消息类型：

* RdMiss：读未命中
* WtMiss：写未命中

需要通过总线找到相应数据块的最新副本，然后调入本地 Cache 中。

还可能有：

* Invalidate：作废消息，不引起调块

响应来自 CPU 的请求：

* 不发生替换：
    <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260620133713005.png){ loading=lazy width="70%" } </figure>
    * 如图，如果 Cache 块已经处于被修改状态，则直接响应读命中/写命中，状态不变；
    * 如果 Cache 块处于共享状态，对于读命中则直接响应，状态不变；对于写命中则发出作废消息，状态变为修改状态；
    * 如果 Cache 块处于无效状态，则发出 RdMiss / WtMiss 消息，状态变为共享状态/修改状态。
* 发生替换：当前数据块让出空间要被其他数据块替换。
    <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260620134218075.png){ loading=lazy width="70%" } </figure>
    * 如图，如果 Cache 块处于修改状态，对于写请求，需要写回主存 + 发 WtMiss，状态不变；对于读请求，需要先写会主存 + 发 RdMiss，状态变为共享状态；
    * 如果 Cache 块处于共享状态，对于写请求，需要发 WtMiss，状态变为修改状态；对于读请求，发 RdMiss，状态不变；

响应来自总线的请求：

<figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260620134953740.png){ loading=lazy width="70%" } </figure>

* 如图，如果 Cache 块处于修改状态，对于 RdMiss 请求，需要写回主存，状态变为共享状态；对于 WtMiss 请求，需要写回主存，状态变为无效状态；
* 如果 Cache 块处于共享状态，对于 RdMiss 请求，状态不变；对于 WtMiss 请求，状态变为无效状态；对于 Invalidate 请求，状态变为无效状态；
* 如果 Cache 块处于无效状态，不影响；

## 分布式共享存储器系统结构（DSM/NUMA）

### 目录协议

* **目录**：一个集中的数据结构，对于每个数据块，目录记录了该块的状态以及哪些 Cache 中有该数据块的副本，从而避免了广播。
* **位向量**：目录中每个数据块对应一个位向量，位向量的每一位对应一个处理器，如果该位为 1 则表示该处理器的 Cache 中有该数据块的副本，称为共享集 S。
* 存储块状态：
    * **未缓冲（Uncached）**：该块没有被任何 Cache 缓存；
    * **共享（Shared）**：该块被一个或多个 Cache 缓存，且与主存中的数据块一致；
    * **独占（Exclusive）**：该块被一个 Cache 缓存，且已经被修改，是最新数据，但还没有写回主存，对应处理机被称为该块的拥有者.
* 三种结点：
    * **本地结点**：发出访问请求的结点；
    * **宿主结点**：访问的存储单元的结点；
    * **远程结点**：拥有访问数据块副本的结点。
* 结点之间的消息：
    *  本地 $\rightarrow$ 宿主，$P$ 表示发出访问请求的处理器，$K$ 表示要访问的地址
        * RdMiss(P, K)：读未命中，请求宿主提供，并把 P 加入共享集 S 中；
        * WtMiss(P, K)：写未命中，请求宿主提供，并使 P 成为该块的拥有者；
        * Invalidate(K)：作废消息，让宿主把共享集 S 中的所有处理器的副本作废。
    * 宿主 $\rightarrow$ 远程
        * Invalidate(K)：作废消息，让远程结点把该块的副本作废；
        * Fetch(K)：请求远程结点提供该块的副本，并把远程 Cache 中对应块的状态改为共享状态；
        * Fetch&Inv(K)：请求远程结点提供该块的副本，同时作废该块的副本。
    * 宿主 $\rightarrow$ 本地
        * DReply(D)：数据响应消息，D 是该块的最新数据。
    * 远程 $\rightarrow$ 宿主
        * WtBack(K, D)：写回消息，表示远程结点把该块的最新数据写回主存，是对宿主结点发出的 Fetch / Fetch&Inv 消息的响应。
    * 本地 $\rightarrow$ 被替换块的宿主结点
        * MdSharer(P, K)：需要替换的块 $K$ 未被修改，需要被替换，通知宿主结点把 P 从共享集 S 中移除；如果 S 变为空，则把该块的状态改为未缓冲状态。
        * WtBack2(P, K, D)：需要替换的块 $K$ 已被修改，需要被替换，通知宿主结点把 P 从共享集 S 中移除，并把该块的最新数据 D 写回主存；如果 S 变为空，则把该块的状态改为未缓冲状态。

* 目录协议分类：
    * **全映像目录**：每一个目录项都包含 $N$ 位的位向量，每一位对应一个处理器；
        * 优点：处理简单，速度较快
        * 缺点：存储开销大，目录空间复杂度为 $O(N^2)$，可扩放性差
    * **有限映像目录**：采用位数固定的目录项数，限制每个数据块的共享副本数，例如限定为 $m$ 个副本，目录项所需的位数为 $m\times\left\lceil\log_2 N\right\rceil$
        * 优点：一定程度上提高了可扩放性，减少了目录占用空间
        * 缺点：当共享副本数超过 $m$ 时，需要进行驱逐
    * **链式目录**：用一个目录指针链表来表示共享集合
        * 优点：不受共享副本数的限制，又保持了可扩展性

??? info "写作废协议中（采用写回法），Cache块的状态转换图"
    <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260620151345418.png){ loading=lazy width="70%" } </figure>
    
    * 对于来自处理器的请求
        * 若数据块处于无效状态，则分别发出 RdMiss / WtMiss 消息，调入该块后，状态变为共享状态/修改状态；
        * 若数据块处于共享状态：
            * 对于读请求且读命中，则状态不变；
            * 对于写请求且写命中，则发出 Invalidate 消息，状态变为修改状态；
            * 对于读请求且读未命中，则发出 RdMiss 消息，替换并调入该块后，状态不变；
            * 对于写请求且写未命中，则发出 WtMiss 消息，替换并调入该块后，状态变为修改状态；
        * 若数据块处于修改状态：
            * 对于读请求且读命中，则状态不变；
            * 对于写请求且写命中，则状态不变；
            * 对于读请求且读未命中，发出 RdMiss 消息，在替换前写回原块并调入新块后，状态变为共享状态；
            * 对于写请求且写未命中，发出 WtMiss 消息，在替换前写回原块并调入新块后，状态不变。
    * 对于来自总线的请求
        * 若数据块处于修改状态：说明该块在当前 Cache 中是最新的，其他 Cache 中的副本已经被作废。
            * 对于 RdMiss 请求，把该块写回主存，并把状态变为共享状态；
            * 对于 WtMiss 请求，把该块写回主存，并把状态变为无效状态（因为远程处理器需要写该块，因此对当前处理器来说应将该块作废）
        * 若数据块处于共享状态
            * 对于 RdMiss 请求，状态不变；
            * 对于 WtMiss 请求，把该块作废，状态变为无效状态；
            * 对于 Invalidate 请求，把该块作废，状态变为无效状态；


??? info "写作废协议中（采用写直达法 + 不按写分配），Cache块的状态转换图"
    <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260620151607306.png){ loading=lazy width="70%" } </figure>

    * 写分配指的是当写未命中时，Cache 控制器会把该块调入 Cache 中，然后再进行写操作。
    * 写不分配指的是当写未命中时，Cache 控制器不会把该块调入 Cache 中，而是直接把数据写入主存中。
    * 对于来自处理器的请求
        * 若数据块处于无效状态：
            * 对于读请求，发出 RdMiss 消息，调入该块后，状态变为共享状态；
            * **对于写请求，直接写入主存，发出 Invalidate 消息（将其他 Cache 中的副本作废），Cache 状态仍为无效状态**；
        * 若数据块处于共享状态：
            * 对于读请求且读命中，则状态不变；
            * 对于写请求且写命中，则发出 Invalidate 消息，状态变为修改状态；
            * 对于读请求且读未命中，则发出 RdMiss 消息，替换并调入该块后，状态不变；
            * **对于写请求且写未命中，则直接写入主存，发出 Invalidate 消息，自己的 Cache 状态也变为无效状态**；
        * 若数据块处于修改状态：
            * 对于读请求且读命中，则状态不变；
            * 对于写请求且写命中，则状态不变；
            * 对于读请求且读未命中，发出 RdMiss 消息，**直接替换，无需写回**，调入新块后，状态变为共享状态；
            * 对于写请求且写未命中，则直接写入主存，发出 Invalidate 消息，**自己的 Cache 状态也变为无效状态**；
    * 对于来自总线的请求
        * 若数据块处于修改状态：当前块也不可能比主存新，不用关心是否写回主存。
            * 对于 RdMiss 请求，把状态变为共享状态；
            * **收不到 WtMiss 请求，因为远程结点的写操作直接写入主存**；
            * 对于 Invalidate 请求，把该块作废，状态变为无效状态；
        * 若数据块处于共享状态
            * 对于 RdMiss 请求，状态不变；
            * 同样收不到 WtMiss 请求；
            * 对于 Invalidate 请求，把该块作废，状态变为无效状态；
        * 若数据块处于无效状态，不影响。
