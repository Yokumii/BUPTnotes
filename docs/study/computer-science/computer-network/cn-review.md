## 一、计算题

### 1.1 CRC 检错码计算

- 看给出的多项式 $G(x)$ 的最高位 $r$，则在数据位后添加 $r$ 个 $0$ 后再进行除法；
- 这里的除法不同于常规的多项式除法，是**模 2 除法，即按位异或**；
- 往往和 HDLC 协议结合出题，只需注意：
    - HDLC 协议采用比特填充；
    - HDLC 等协议差错校验和成帧的顺序是：

???+ note "发送方处理步骤"
    计算并添加校验码 → 0 比特填充 → 添加收尾标记 `01111110`

???+ note "接收方处理步骤"
    收到物理层的 01 比特串 → 首先根据首尾标记位提出帧 → 删除发送方添加的零比特（比特删除） → 最后进行差错校验

### 1.2 帧填充与识别

### 1.4 最大传输速率问题

熟悉三个公式，注意后两者计算的是**理论上限**：

$$
\text{比特率} = \text{波特率} \times \log_2 V
$$

其中 $V$ 为每个信号单元可表示的离散状态数。

**Nyquist 定理**（无噪声信道）：

$$
C_{\max} = 2B \log_2 V
$$

**香农定理**（有噪声信道）：

$$
C_{\max} = B \log_2(1 + S/N)
$$

其中 $B$ 为信道带宽，$S/N$ 为信噪比。

!!! tip "做题提醒"
    题目若同时给出信噪比和信号状态数，需分别用 Nyquist 和香农公式计算，取两者中**较小值**作为实际理论上限。

### 1.5 分组交换和电路交换延时计算

#### 电路交换

步骤：建立连接 → 传输数据 → 连接中止，释放资源。

时延公式：

$$
T_{\text{circuit}} = T_{\text{establish}} + T_{\text{trans}} + h_{\text{hop}} \times T_{\text{prop}} + T_{\text{release}}
$$

??? info "电路交换优缺点"
    **优点**
    - 稳定，时延低（Small Delay, Good Quality）
    - 交换过程中控制方式简单

    **缺点**
    - 连接建立的时间较长
    - 带宽固定，不适用于多样的传输服务
    - 当两端都没有数据要发送时，造成信道资源浪费

#### 分组交换

步骤：将较大的数据包分为多个 Packet 进行传输，每个 Packet 有独立路由，每跳需存储转发。

忽略排队和处理时延，时延公式：

设数据大小 $M$，每个分组大小 $P$，信道数据率 $B$，则分组数 $n = \lceil M/P \rceil$，每个分组传输时延 $T_{\text{trans}} = P/B$，每跳传播时延 $T_{\text{prop}}$。

$$
T_{\text{packet}} = (n - 1) \times T_{\text{trans}} + h \times (T_{\text{prop}} + T_{\text{trans}})
$$

??? info "分组交换优缺点"
    **优点**
    - 信道效率提高
    - 速率适配
    - Packet 可以在节点较忙时先被缓存再发送（排队制，可引入优先级机制）

    **缺点**
    - 网络更加复杂
    - 传播过程中的时延更长
    - 没有 QoS 服务质量保证

### 1.6 最小帧长度的计算

以太网或其他使用 CSMA/CD 技术的 LAN，都需满足条件：

$$
\frac{M_{\min}}{B} = 2\tau
$$

确保有足够的时间检测冲突。

对于 10M 以太网，$2\tau = 51.2\text{us}$，据此得到最小帧长度为 **64 Bytes**。

???+ note "以太网帧长度范围"
    对于 10 兆以太网，数据帧长度范围为 46 Bytes ～ 1500 Bytes，加上 18 位控制字符，最终帧长度范围为 **64 Bytes ～ 1518 Bytes**。

    帧的地址字段长度为 6 Bytes。

## 二、简答题

### 2.1 参考模型

#### OSI 参考模型

| 层次 | 数据单元 | 主要功能 |
|------|---------|---------|
| 应用层 | Message 消息 | 提供应用相关的服务 |
| 表示层 | Message 消息 | 信息的表示、加密、压缩等 |
| 会话层 | Message 消息 | 进程会话控制、令牌管理、同步 |
| 传输层 | Segment 段 | 实现可靠的端到端的传输 |
| 网络层 | Packet 分组 | 路由转发、拥塞控制、服务质量管理和网络互联 |
| 数据链路层 | Frame 帧 | 成帧、差错控制、流量控制 |
| 物理层 | Bit 比特 | 比特流传输 |

#### TCP/IP 参考模型

- **网际层**：分组交换、路由，采用 IP 协议；
- **传输层**：分为 TCP（可靠的面向连接的服务）和 UDP（不可靠的无连接的服务）；

#### IEEE 802 参考模型

将数据链路层划分为两个子层：

- **逻辑链路控制子层（LLC）**：为网络层提供统一的接口；流量控制；差错控制；网桥；
- **介质访问控制子层（MAC）**：成帧；差错检查；MAC 地址；介质访问多路控制；局域网交换，VLAN；

???+ question "OSI 与 TCP/IP 各两点不足？（2013 期中）"
    **OSI 模型的缺点**

    1. 实现复杂度高：七层划分过于细致，导致协议实现成本高，尤其在会话层和表示层功能重复（如加密、压缩等），实际应用中常被合并；
    2. 缺乏灵活性：属于理论标准，未充分考虑实际网络需求（如互联网的 IP 协议）；

    **TCP/IP 模型的缺点**

    1. 层次划分粗糙：可能导致协议功能边界模糊；
    2. 无明确服务/接口定义：OSI 模型严格区分服务、接口和协议，而 TCP/IP 模型仅关注协议实现，缺乏标准化接口描述，不利于系统集成；

???+ question "协议、服务、接口的概念与关系？（2013 期中）"
    **协议**
    ：两个系统同一层的对等实体之间进行通信需要共同遵守的规则。

    **服务**
    ：某层实体对于上一层实体的支持，即对上一层提供的功能集合。

    **接口**
    ：定义某层实体对于上一层提供的服务原语操作。

    协议是**水平的**，服务是**垂直的**。一层协议的实现需要下层的服务，本层服务的实现需要协议的支持。注意，本层协议改变不一定会导致本层服务改变；但本层服务改变会影响相邻上一层的服务。

    **PDU 与服务原语的区别**：PDU 为同层之间的水平通信（包含协议头和上层数据），服务原语为层间的垂直通信（用户与服务的交互命令）。PDU 是实现协议的载体，服务原语触发协议动作。

???+ question "层次化设计原则？（2015 期中）"
    1. **各层应执行定义明确的函数**——每层需专注于解决特定类型的问题或提供特定服务，功能的划分应清晰，避免不同层次的任务相互混淆。
    2. **层间边界的选择应使接口处的信息流最小化**——相邻层之间的交互应尽可能简单，一层只向其上一层提供必要的、最小化的服务，减少不必要的依赖和信息传递。
    3. **层次的数量应适中**——既不能太多（避免架构过于庞大和复杂、增加头部开销），也不能太少（避免不同功能被不恰当地合并到同一层），需要在功能清晰度和整体复杂性之间找到平衡。

### 2.2 物理层与 PSTN

#### 交换电话网结构

PSTN（Public Switched Telephone Network，公用交换电话网）由本地环路和中继两部分构成。

**本地环路（Local Loop）**

- 进行模拟信号传输，使用**双绞线**，从家到端局；
- 早期只包括电话线（300 Hz ～ 3400 Hz），后期由于加入电脑等设备需要传送数字信号，所以先通过 Modem，再通过 CodeC；

| 功能 | 拨号上网，将数字信号调制成适合带宽传输的模拟信号 | 同 Modem |

???+ question "什么因素限制了 Modem 拨号上网的带宽？为什么上行和下载速度不相同？（2012/2014/2015 期中）"
    上行受到模拟信号转数字信号的信噪比影响，根据香农公式，最大数据率受到限制；而下行不会受到此限制，因此 ADSL 为非对称传输：下行速率远高于上行速率。

???+ question "为什么普通电话线无法传送计算机网络数据，而采用 ADSL 电话线就可以传送？（2015 期中）"
    ADSL 使用的电缆扩展了普通电话线的带宽到 3400 Hz 以上。普通电话线有滤波器将带宽限制在语音范围，ADSL 不需要滤波器。

???+ question "ADSL 用户线的完整问答（2020 期中）"
    - **传输介质**：普通电话线，即 3 类双绞线 UTP3，但扩展了带宽到 3400 Hz 以上；
    - **复用技术**：模拟信号，采用频分复用 FDM；
    - **数据链路层协议**：端到端采用 PPP 协议，以字符为单位；
    - **向上层提供的服务**：非对称数据传输（下行远高于上行）；为网络层多种协议提供支持、身份认证、协商 IP 等；
    - **成帧技术**：字符填充法；

???+ question "两台计算机用 Modem 利用电话线通信，不适合的成帧方法？（2019 期中）"
    Modem 接收和传送数据的单位是字节而不是位/比特，因此不适合用比特填充法成帧。

???+ question "传输介质速率比较？（2012 期中）"
    传输速率/带宽：双绞线 < 细缆 < 粗缆 < 光纤。

### 2.3 数据包分片过程

数据链路层（以太网）、网络层（IP 协议）、传输层（TCP 协议）都涉及分片操作。

???+ note "层与层之间的封装过程"
    1. 应用层的数据交给传输层后，这部分数据即 TCP 的有效载荷；
    2. TCP 是面向字节流的，故有效载荷不能超过 MSS Bytes；TCP 首先对数据进行了一次分片，分成不同的 TCP 报文；
    3. TCP 对其进行封装，加上至少 20 Bytes 的 TCP Header；
    4. 交给网络层后，网络层同样对其进行封装，加上 20 Bytes ～ 60 Bytes 的 IP Header；
    5. IP Header + TCP Header + Payload 完成封装，交给数据链路层，作为 Frame 的 Data 部分；
    6. 数据链路层为其加上 18 Bytes 的控制字段，封装成帧，最终在物理层中实际传输；

对于以太网，MTU = 1500 Bytes（最大传输单元，不包含控制字段），所以反推出 MSS 不能超过 $1500 - 20 - 20 = 1460$ Bytes。

!!! warning "为什么需要 MSS？"
    网络层是不可靠的，尽力而为，没有像 TCP 一样高效的重传机制。如果不考虑 MTU，让 IP 层直接对 TCP 报文分片，一个 TCP 报文会被划分为多个 IP 包。传输过程中若其中一个 IP 包分片丢失，IP 协议无重传机制，需要重传**所有 IP 包分片**，且只有超时后 TCP 才能触发重传，效率极低。

    引入 MSS 后，确保了一个 TCP 报文不会被 IP 协议分片，即 1 个 IP 包对应 1 个 TCP 报文。TCP 建立连接的过程中，双方会协商好 MSS 的大小。

### 2.4 QoS 与保证转发

<figure markdown="span">
  ![QoS 保证转发](https://webp-pic.yokumi.cn/2026/01/20260101155048303.png){ loading=lazy width="70%" }
</figure>

1. 所有业务被划分为 4 个优先级；
2. 通过 Traffic Policer 的令牌桶机制进行流量整形；
3. 在经过 Traffic Policer 时，每个优先级下又被分类为 3 种丢弃优先级（即丢包的可能性大小）；
4. 最终实际上有 12 种服务等级；
5. 每个 Packet 的 IP Header 的 **ToS 字段**会携带 DSCP（6bits）+ ECN（2bits）：
    - **DSCP**（Differentiated Services Code Point，服务等级）；
    - **ECN**（Explicit Congestion Notification，拥塞控制）；
6. 路由器接收被划分后的包，根据以下两种机制进行分组调度：
    - **WFQ**（Weighted Fair Queuing，加权公平队列）：按照优先级进行公平调度；
    - **RED**（Random Early Detection，随机早期检测）：采用主动丢弃机制，被丢弃的概率就是前面划分的丢弃优先级；

### 2.5 滑动窗口协议

???+ question "重发计时器与 ACK 计时器的作用与关系？（2013 期中）"
    **重发计时器 Frame_Timer**
    ：在发送方发送一个帧时启动，若在规定时间内未收到该帧对应的 ACK，则超时重传。每个帧对应一个计时器，用于确保数据最终被可靠地传送到接收方。

    **ACK 计时器 ACK_Timer**
    ：一般只在选择重传协议中使用。在接收方从接收窗口下沿依次提交收到的帧并向前滑动时启动；若在规定时间内接收方有数据要发送，则停止 ACK_Timer，采用 Piggybacking 将 ACK 和数据一起发送给发送方；若 ACK_Timer 超时，则单独发送 ACK 给发送方。ACK_Timer 通过延时确认提高了网络效率，减少了单独的 ACK 报文数量。由于采用累积 ACK 的方式，接收方只需一个 ACK_Timer。

    时间关系：

    $$2t_{\text{prop}} + \text{ack\_timer} < \text{frame\_timer}$$

    左边表示从发送方发送数据帧到接收方返回 ACK 的最大时间，右边是发送方重传计时器的超时时间。小于关系避免了发送方在 ACK 尚未到达前误判数据帧丢失并进行不必要的重传。

### 2.6 共享信道协议

???+ question "评价共享信道协议优劣的两个主要指标？（2018 期中）"
    **低负载情况下的时延**和**高负载下的吞吐量**（或信道利用率）。

    低负载下适合用竞争的方法（即 1-persistent CSMA）；而 $p$ 越小，负载高时发送帧的随机化越好，冲突越小，吞吐量越高。

???+ question "什么是隐蔽站问题？802.11 如何解决？（2020 期中）"
    **隐蔽站问题**
    ：假如 A 需要向 B 发送数据，但站点 C 位于 A 的监听范围之外而处于 B 的范围内，C 同时也要向 B 发送数据。由于 A 无法监听到 C，仍会发送数据造成冲突。

    CSMA/CA 通过 RTS/CTS 机制解决此问题。

???+ question "提高信道利用率的措施？（2015 期中）"
    增加发送字节的长度、采用滑动窗口技术等。

### 2.7 无线通信

???+ question "WLAN 中的 TXOP 机制？（2019 期中）"
    TXOP（Transmission Opportunity）：传统信道分配方式是站点每次发送一帧，即"你发一帧我发一帧"，但对于数据率大的站点不公平，且低速站点会拉低吞吐量。使用 TXOP 机制时，每个站点获得相等的发送时间，如有 $n$ 个站点，每个站点速率为 $c_i$，则实际传输中每个站点速率为 $\frac{c_i}{n}$，保证了公平性。

???+ question "无线局域网的协议标准？虚拟载波监听技术？（2019 期中）"
    **协议标准**：IEEE 802.11。

    **虚拟载波监听技术**：
    1. 每个站点维持一个 NAV（Network Allocation Vector，网络分配向量）；
    2. 发送方在发送帧时携带一个 NAV，表示信道将被占用的时长；
    3. 接收方在接收到帧后更新本地 NAV，根据 NAV 确定需要的退避时间，以避免冲突。

### 2.8 网络设备

- **Repeater（中继器）**：互联设备，属于物理层；用于将两个总线型的以太网进行连接；
- **Bridge（网桥）**：属于数据链路层；用于将两个局域网进行互联；

???+ question "网桥和交换机的共同点和区别？"
    **共同点**：都是数据链路层设备。

    **不同点**：

    1. 网桥主要用软件处理；交换机的处理是硬件层面的；
    2. 网桥同时只能分析和处理一帧，交换机一次性可以处理大量帧；
    3. 网桥采用存储转发方式，交换机还可以通过直通 Cut-Through 等方式加快传输速率；

???+ question "能隔离广播风暴的设备？（2018 期中）"
    路由器 和 VLAN 交换机，两者分别工作在不同的层。

### 2.9 虚拟局域网 VLAN

- 将局域网在逻辑上划分为多个广播域；
- 每个 VLAN 都有一个唯一的标识符 VLAN ID，通过这个实现区分；
- 不支持 VLAN 的交换机无法识别帧中的 VLAN ID；

???+ question "VLAN 交换机可隔离广播和组播报文吗？说明原因？（2019 期中）"
    可以隔离。VLAN 通过在数据链路层进行逻辑隔离，默认情况下会**隔离广播和未知组播**报文，将其限制在各自的 VLAN 内部，从而提高网络性能和安全性。
