# 事务

## 事务的概念

事务是构成单一逻辑工作单元的操作集合。即使事务中包含多个操作，DBMS 也必须保证这些操作要么全部执行，要么全部不执行，以维护数据的完整性。

## ACID 性质

ACID 是事务必须满足的四个核心性质：

Atomicity（原子性）
: 事务中的所有操作要么全部完成，要么全部不执行。由**事务管理组件**负责保证。

Consistency（一致性）
: 事务的执行必须保持数据库的一致性状态——即从一个一致性状态转换到另一个一致性状态。由**业务逻辑**负责保证。

Isolation（隔离性）
: 每个事务的执行不能被其他事务干扰，即使并发执行也是如此。由**并发控制组件**负责保证。

Durability（持久性）
: 事务一旦提交，其对数据库的修改必须是永久的，即使系统发生故障也不丢失。由**恢复机制**负责保证。

## 事务状态

事务在执行过程中经历一系列状态转换：

- **活跃（active）**：事务正在执行操作
- **部分提交（partially committed）**：事务执行完最后一条操作，等待修改写入磁盘
- **提交（committed）**：事务成功完成，修改永久保存
- **失败（failed）**：事务无法继续正常执行
- **中止（aborted）**：事务已回滚，恢复到开始前的状态

状态转换路径：

- 正常路径：活跃 → 部分提交 → 提交
- 异常路径：活跃 → 失败 → 中止

## 并发执行

允许多个事务并发执行的优势：

- **提高资源利用率**：一个事务在等待 I/O 时，CPU 可处理其他事务
- **缩短平均响应时间**：短事务不必等待长事务完成

### 可串行化

如果一个并发调度的执行结果与某个串行调度的执行结果相同，则称该并发调度是**可串行化的**。可串行化是并发调度正确性的判别标准。

## 冲突可串行化

### 冲突操作

两个操作构成冲突，当且仅当它们满足：

1. 属于不同事务
2. 访问同一数据项
3. 至少一个是写操作

冲突操作包括：read-write、write-read、write-write。两个冲突操作的顺序不能交换。

### 冲突等价

如果两个调度可以通过交换非冲突操作的顺序相互转换，则它们是**冲突等价**的。

### 冲突可串行化

如果一个调度冲突等价于某个串行调度，则该调度是**冲突可串行化**的。

### 前驱图方法

前驱图用于检测冲突可串行化：

- 顶点：事务 $T_i$
- 边 $T_i \to T_j$：在调度中 $T_i$ 的操作与 $T_j$ 的操作冲突，且 $T_i$ 先执行

判断规则：

- 前驱图有环 → 不冲突可串行化
- 前驱图无环 → 冲突可串行化，对前驱图做拓扑排序即可得到等价的串行顺序

## 可恢复性

### 可恢复调度

如果 $T_i$ 读取了 $T_j$ 写入的数据，则 $T_i$ 必须在 $T_j$ **提交之后**才能提交。这样的调度称为可恢复调度。

### 级联回滚

当 $T_j$ 中止时，所有读取了 $T_j$ 未提交数据的事务也必须回滚，这些事务又可能导致更多事务回滚——即级联回滚：

### 无级联调度

无级联调度要求：$T_i$ 只能读取已提交的数据。每个无级联调度都是可恢复调度，但反之不然。
