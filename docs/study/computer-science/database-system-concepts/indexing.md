# 索引

## 索引的目的

!!! abstract "索引的基本概念"
    索引用于加速搜索操作。每个索引项由**搜索键（search-key）**和**指针（pointer）**组成，通过搜索键快速定位到对应记录。

## 有序索引

有序索引
: 记录按搜索键值排序组织的索引

### 主索引 / 聚集索引

主索引（Primary Index）/ 聚集索引（Clustering Index）
: 搜索键的顺序与文件的物理存储顺序一致。每个文件至多一个主索引。

    - 通常建立在主键上，但并非必须
    - 索引顺序文件（Index-Sequential File） = 顺序文件 + 主索引

### 辅索引

辅索引（Secondary Index）
: 搜索键的顺序与文件的物理存储顺序不同。一个文件可有多个辅索引。

    - 辅索引**必须是稠密索引**

## 稠密索引与稀疏索引

稠密索引（Dense Index）
: 每个记录都有对应的索引项，无论搜索键是否有序均可使用

稀疏索引（Sparse Index）
: 仅部分记录有索引项，要求文件必须按搜索键有序排列

    - 查找键值 $K$ 时：找到**最大的索引项** $< K$，然后从该索引项指向的记录开始顺序扫描

## 多级索引

多级索引
: 当索引本身过大时，在索引上再建索引，形成多级结构，以减少查找时的 I/O 次数

## 索引更新

### 删除

!!! abstract "删除记录时的索引维护"
    - **稠密索引**：直接移除对应的索引项
    - **稀疏索引**：若被删除记录是索引项所指的第一个记录，则将索引项更新为同一块中的下一个键值

### 插入

!!! abstract "插入记录时的索引维护"
    - **稠密索引**：总是需要插入新的索引项
    - **稀疏索引**：仅当新记录成为某个块的第一条记录时，才插入新的索引项

## B+ 树索引

B+ 树索引
: 一种平衡的多级索引结构，广泛用于数据库系统。所有叶子节点在同一层，支持高效的范围查询与点查询。

## 散列索引

散列索引
: 使用散列函数将搜索键映射到桶（bucket），适用于等值查询。

## 索引的 SQL 语句

创建索引
: `CREATE INDEX index_name ON table_name (attribute_list)`

删除索引
: `DROP INDEX index_name`
