# SDN 软件定义网络

## SDN 与传统路由器的区别

1. 传统路由器的痛点：
    * **紧耦合与封闭性**：传统网络设备（如路由器/交换机）是**软硬件紧耦合**的，设备配置主要依靠静态手动配置（CLI/GUI），缺乏外部可编程性，创新周期极其缓慢；
    * **分布式控制**：每个路由器内部都独立运行路由协议（如OSPF/BGP），自己维护链路状态数据库和路由表，属于分布式控制平面
    <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260629204034760.png){ loading=lazy width="70%" } </figure>
2. 控制平面与转发平面分离的思想 (SDN核心)：
    * SDN 的核心理念是将网络设备的**控制平面**（大脑）与**数据转发平面**（四肢）进行分离，并实现**可编程**化的**集中控制**
    * 底层设备被剥离了复杂的控制逻辑，变成了纯粹的“哑终端”（专用的数据包转发硬件），而控制功能被转移到了**逻辑集中的服务器（SDN控制器）**上

## SDN 的基本架构

* SDN ＝ **控制与转发分离** + **逻辑集中控制** ＋ **网络资源能力状态开放**

<figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260629204403936.png){ loading=lazy width="70%" } </figure>

* **三层架构**：
    * **数据平面（基础设施层）**：由若干**网元（转发设备）**组成，每个网元包含一个或多个 SDN 数据路径，是一个被管理的资源在逻辑上的抽象集合。负责高速的数据包处理和转发；
    * **控制平面（控制层）**：由逻辑集中的 **SDN 控制器**（如 OpenDaylight 原生内置分布式集群、Ryu 依赖外部分布式协调器）组成，任务是：
        1. 将 SDN 应用层请求转换到 SDN 数据路径（向下）；
        2. 为 SDN 应用层提供底层网络的抽象模型（向上）。
    * **应用平面（业务层）**：由若干 **SDN 应用**（如路由、负载均衡、防火墙等）组成，调用控制器提供的开放接口（**北向接口**）与 SDN 控制器交互，来编程和控制网络行为。
* **南向与北向接口的作用**：
    * **南向接口（控制 - 数据平面）**：连接控制平面与数据平面（如**控制类协议 OpenFlow**, **配置类协议 NETCONF**）。作用包括：**对所有转发行为进行控制**、设备性能查询、统计报告、事件通知等（**收集数据平面信息**）。
    * **北向接口（应用 - 控制平面）**：连接应用平面与控制平面（最典型的是 REST API），**开放**，与厂商无关。作用包括：**提供抽象的网络视图、使应用能直接控制网络行为**。

## 流表的结构与作用

在数据平面中，基本功能包括转发决策（用**流表**代替了传统网络设备二层和三层转发表）、背板转发（经背板从入端口转发到出端口）、输出链路调度（QoS的支持）。

* OpenFlow 交换机：**OpenFlow 表项 + 安全通道**
* OpenFlow 流表：流表是 OpenFlow 对网络设备数据转发功能的抽象，包含若干个**流表项（Flow Entry）**，每个流表项由：
    * **包头域/匹配域**（Match Fields）：用于对交换机接收到的数据包的包头内容进行匹配；
        * 10 元组以上，可涵盖 L2 ~ L4 层（MAC, VLAN, IP, TCP/UDP端口等）。
        * 逐个匹配，匹配成功则执行对应的动作（Action），匹配失败则继续查找下一个流表项，直到匹配成功或流表查找结束。
        * 若分组匹配多个流表项，则选择**优先级最高（编号最大）**的流表项执行动作。
    * **计数器**（Counters）：用于统计数据流量相关信息，基于表、流、端口或队列进行流量统计（包数、字节数）；
    * **动作**（Actions）：用于指示交换机在收到匹配数据包后如何对其进行处理（如正常转发、修改MAC/IP头、丢弃、或送往控制器）；

> OpenFlow 1.1/1.3 增加了组表和计量表以支持 QoS 限速等功能。

!!! note "流表和路由表的区别"
    * **路由表**：传统路由表仅基于目的 IP 地址 (IP dst) 进行匹配，且动作单一（仅决定下一跳出接口），无法更改、不可编程。
    * **流表**：流表是 OpenFlow 对网络设备数据转发功能的抽象，表项包括了网络各个层次的配置信息，且动作极其丰富（支持丢弃、修改头部报文、多端口广播、上送控制器等），支持 QoS 控制。

## 南向接口协议

### OpenFlow 协议

#### 消息类型

用于控制器与 OpenFlow 交换机之间的通信，支持 3 种消息类型：

* **Controller-to-Switch（控制器-交换机）**：控制器下发指令给交换机，用来管理或获取 OpenFlow 交换机的状态
    * `Features`: 
        * **`Features-Request`**: 控制器向交换机发送的请求，用于获取交换机基本信息；
        * **`Features-Reply`**: 交换机返回的基本信息，包含DPID（交换机唯一标识）、端口数、缓冲区等能力。
    * `Configuration`:
        * **`Set-Config`**: 控制器设置交换机的配置参数（交换机无需显式回复）；
        * `Get-Config`: 控制器获取交换机的配置参数；
    * `Modify-State`:
        * `Port-Mod`: 控制器管理交换机的端口状态；
        * **`Flow-Mod`**: 控制器管理交换机的流表项，通常是在收到交换机的 `Packet-In` 消息后，向交换机下发流表项指导后续同一条流的处理；
    * `Read-State`
    * `Send-Packet`:
        * **`Packet-Out`**: 控制器向交换机发送指令，将触发 Packet-in 的原始数据包从特定的端口（Port）发出去；
    * `Barrier`: `Barrier-Request` 控制器确保交换机在处理完之前下发的消息后再处理后续消息，交换机通过 `Barrier-Reply` 回复；
* **Asynchronous（异步）**：交换机向控制器发送网络事件或交换机状态变化
    * **`Packet-In`**: 收到的数据分组如果没有匹配的流表项，或者动作指定端口为控制器，将数据包（或部分内容）封装在 Packet-in 消息中发送给控制器
    * `Flow-Removed`, `Port-Status`, `Error`
* **Symmetric（对称）**：交换机和控制器之间的双向消息，用于建立连接/心跳检测
    * `Hello`, `Echo`

### NETCONF 协议 & YANG 数据建模语言

* **NETCONF**：由 IETF 标准化的**网络配置协议**。它采用 **XML 编码**和 **RPC（远程过程调用）**南向接口。
    * 允许 SDN 控制器以**编程方式**对网络设备进行**统一配置**。
    * 在 SDN 的多租户环境中，NETCONF 可用于动态创建和配置虚拟网络资源（如 VXLAN、VLAN、QoS 策略），为不同租户隔离配置空间。
    * 采用了分层协议模型：传输层 - 消息层 - 操作层 - 内容层。
* **YANG**：是一种**数据建模语言**，与 NETCONF 紧密结合，定义了**数据的结构和约束**，不规定传输方式。

## 基于北向接口的应用开发方式（REST API）

* **REST / RESTful API（表述性状态传递）**是一种基于 **HTTP** 协议的**应用编程接口**。
    * 将控制器基本功能模块和各网元看作网络资源，使用 GET（查询拓扑/流表）、POST（下发流表）、PUT/DELETE 等标准 HTTP 方法操作相应资源的数据；
    * Ryu、OpenDaylight、Floodlight 等控制器都使用 REST API 作为北向接口；
* **RESTCONF**：
    * 本质上是 NETCONF 协议基于 HTTP 的 RESTful 版本，两者都使用 YANG模型定义数据；
    * 在编码上同时支持 XML 和 JSON，因此更轻量、易读；
    * RESTCONF 通常作为北向接口，NETCONF 作为南向接口；

## SDN 的工作流程

以构建“最短路径转发”为例，SDN 的标准工作流程分为三大阶段：

1. **阶段一：LLDP 拓扑发现循环（构建地图）**
    * 控制器通过 `Packet-Out` 构造 LLDP 报文让交换机发往物理链路。对端交换机收到后，因无匹配项触发 `Packet-In` 上报控制器，控制器借此解析出全局的链路拓扑图。
2. **阶段二：主动式路径下发（预埋路牌）**
    * SDN 路由应用通过 **北向接口(REST API, HTTP GET)** 获取最新拓扑。
    * 应用计算出最短路径，通过 **北向接口(HTTP POST)** 下发对应流表给控制器。
    * 控制器通过 **南向接口(`OFPT_FLOW_MOD`)** 将具体的流表规则写入沿途交换机的硬件（TCAM）中。
3. **阶段三：业务数据高速转发**
    * 真实业务数据包到达交换机时，**直接命中流表硬件表项**，按预设的端口极速转发，**不再触发 `Packet_In` 上送控制器**。

## SDN 的应用

* **Overlay 网络（数据中心网络的应用）**：通过网络虚拟化技术，在同一张 Underlay 网络上构建出的一张或者多张虚拟的逻辑网络
    <figure markdown="span">   ![](https://webp-pic.yokumi.cn/2026/06/20260629223308374.png){ loading=lazy width="70%" } </figure>
    * 控制器可以直接向 Leaf 节点（即 VTEP）下发流表，自动完成隧道路径的计算与建立，实现了 **Overlay 网络的自动化编排**。
    * **Overlay 屏蔽了物理网络的异构性**，而 **SDN 则屏蔽了隧道管理的复杂性**；
* **SD-WAN（在广域网的应用）**：实现了转控分离，控制器**集中管理**下发策略，支持**零接触部署 (ZTP)** 以及根据丢包率、时延等链路质量进行**动态灵活选路**，极大降低了传统 MPLS 专线的昂贵成本。
