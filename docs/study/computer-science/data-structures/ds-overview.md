# 数据结构概述

数据结构是计算机科学的核心基础课程，研究数据的组织、存储和运算方式，为算法设计与程序实现提供基础支撑。

## 基本概念

数据结构中涉及一组层次递进的基本概念，从最底层的不可分割单位到整体结构：

数据项（Data Item）
: 构成数据元素的**不可分割的最小单位**。例如，一个学生记录中的"学号""姓名"等字段即为数据项。

数据元素（Data Element）
: 数据的基本单位，由若干数据项组成，在程序中通常作为一个**整体**进行处理。例如，一个学生记录就是一个数据元素。

数据对象（Data Object）
: 具有**相同性质**的数据元素的集合，是数据的一个子集。例如，所有学生记录构成的集合即为一个数据对象。

数据（Data）
: 能被计算机程序处理的**符号的总称**，是信息的载体。数据涵盖数字、字符、图像、音频等各种形式。

数据结构（Data Structure）
: 相互之间存在一种或多种**特定关系**的数据元素的集合。数据结构不仅包含数据元素本身，更重要的是描述了元素之间的逻辑关系。

!!! tip "概念层次"
    数据项 → 数据元素 → 数据对象 → 数据结构，层层组合，逐步抽象。理解这一层次关系有助于把握数据结构的本质——**关系**才是核心。

## 逻辑结构与存储结构

数据结构的研究可以从三个维度展开：逻辑结构、存储结构和数据运算，三者之间密切相关。

### 逻辑结构

逻辑结构指数据元素之间的**逻辑关系**，与存储方式无关，是从用户视角看到的结构。逻辑结构可分为以下四类：

集合
: 数据元素之间除了"同属一个集合"的关系外，没有其他关系。

线性结构
: 数据元素之间存在**一对一**的关系，如线性表、栈、队列。

树形结构
: 数据元素之间存在**一对多**的层次关系，如树、二叉树。

图状结构
: 数据元素之间存在**多对多**的网状关系，如图。

???+ note "逻辑结构的分类依据"
    逻辑结构的分类依据是元素之间关系的**约束程度**——从无约束（集合）到最严格约束（线性），再到层次约束（树）和任意约束（图），约束程度递减而复杂度递增。

### 存储结构

存储结构（也称物理结构）指数据元素在计算机存储器中的**存储方式**，是逻辑结构在内存中的映射。常见的存储结构包括：

顺序存储
: 用一组**连续的存储单元**依次存放数据元素，元素之间的逻辑关系通过物理位置的相邻来体现。优点是存储密度高、随机访问方便；缺点是插入和删除操作需要移动大量元素。

链式存储
: 用一组**任意的存储单元**存放数据元素，元素之间的逻辑关系通过**指针**来体现。优点是插入和删除灵活；缺点是每个节点需额外存储指针，存储密度较低。

索引存储
: 在存储数据元素的同时建立**附加的索引表**，通过索引快速定位元素。

散列存储
: 根据元素的关键字直接计算出其存储地址（**哈希函数**），实现快速查找。

### 数据运算

数据运算是对数据结构施加的操作，如插入、删除、查找、排序、遍历等。运算的定义依赖于**逻辑结构**，而运算的实现依赖于**存储结构**。

!!! warning "三者关系"
    - **逻辑结构**是数据结构的抽象定义，决定了运算的**功能**。
    - **存储结构**是逻辑结构的具体实现，决定了运算的**效率**。
    - 同一种逻辑结构可以采用不同的存储结构实现，不同存储结构下同一运算的性能差异可能很大。

## 算法评价标准

算法是解决特定问题的一系列有限操作步骤。评价一个算法的好坏，通常从以下几个维度考虑：

### 正确性

算法应当能够正确地解决问题，对所有合法输入都能产生符合预期的输出。正确性是算法的**最基本要求**，一个不正确的算法没有任何价值。

### 可读性

算法应当便于人类阅读和理解。可读性好的算法有利于**调试、维护和交流**，在团队协作中尤为重要。过于追求简洁而牺牲可读性，往往得不偿失。

### 健壮性

算法应对**非法输入**具有合理的处理能力，不会因为意外的输入而崩溃或产生难以追踪的错误。健壮性体现了算法的防御性设计思想。

???+ example "健壮性示例"
    当输入为空数组或包含负数索引时，一个健壮的排序算法应当返回空数组或抛出明确的异常信息，而非产生未定义行为。

### 效率与存储量需求

效率指算法的**时间效率**（执行速度），存储量需求指算法运行所需的**辅助空间**。两者通常通过时间复杂度和空间复杂度来度量。

???+ info "时间与空间的权衡"
    很多情况下，时间效率和空间需求之间存在**此消彼长**的关系——用更多空间换取更快速度（如缓存、哈希表），或用更多时间换取更少空间（如压缩算法）。选择何种策略取决于具体应用场景和资源约束。

!!! note "大数据场景下的补充考量"
    在大数据场景下，支持**分布式和并行处理**的算法更具优势。传统单机算法的时间复杂度分析可能不再适用，需要考虑数据分片、节点通信开销和负载均衡等因素。
