# 大容量存储结构

## 磁盘访问时间

磁盘访问时间由以下步骤组成：

<figure markdown="span">
  ![磁盘访问时间](https://webp-pic.yokumi.cn/2025/12/20251220154158270.png){ loading=lazy width="70%" }
</figure>

1. **寻道时间（Seek Time）**：磁头移动到目标柱面，通常使用平均寻道时间
2. **确定盘面**：选择目标盘面（正反两面均可存储数据）
3. **旋转延迟（Rotational Latency）**：目标扇区旋转到磁头下方，通常使用平均旋转延迟
4. **数据传输时间（Transfer Time）**：传输数据所需时间 = 数据大小 / 传输速率
5. **控制命令时间**：可忽略不计

!!! tip "关键结论"
    磁盘访问时间中，**寻道时间**是最大的性能瓶颈，因此磁盘调度算法的主要目标是最小化寻道时间。

## 磁盘结构

磁盘在逻辑上呈现为**逻辑块的一维数组**，操作系统通过逻辑块号访问磁盘数据。逻辑块到物理位置的映射关系如下：

- **柱面编号**：从外向内递增（0-based），即最外侧柱面编号为 0
- **磁道编号**：从上到下递增
- **扇区编号**：每个磁道内的扇区按顺序编号

逻辑块号 → 物理位置的转换由磁盘控制器完成，操作系统只需提供逻辑块号即可。

## 磁盘调度

磁盘调度的目标：**最小化寻道时间**。

### FCFS（先来先服务）

- 按 I/O 请求到达的顺序依次服务
- 简单公平，但可能导致磁头大幅移动，平均寻道时间较长

<figure markdown="span">
  ![FCFS 磁盘调度](https://webp-pic.yokumi.cn/2025/12/20251220161325787.png){ loading=lazy width="70%" }
</figure>

### SSTF（最短寻道时间优先）

- 每次选择**距当前磁头位置最近**的请求
- 平均寻道时间优于 FCFS
- 缺陷：**可能导致远端请求饥饿**（Starvation）

<figure markdown="span">
  ![SSTF 磁盘调度](https://webp-pic.yokumi.cn/2025/12/20251220161437253.png){ loading=lazy width="70%" }
</figure>

### SCAN（电梯算法）

- 磁头沿一个方向移动，服务沿途请求；到达磁盘末端后**反向**继续服务
- 公平性好，避免饥饿
- 缺陷：刚扫过的区域请求需要等到下次扫描

<figure markdown="span">
  ![SCAN 磁盘调度](https://webp-pic.yokumi.cn/2025/12/20251220164723073.png){ loading=lazy width="70%" }
</figure>

### C-SCAN（循环扫描）

- 仅在**单方向**上服务请求，到达末端后直接返回起始端（返回过程中不服务请求）
- 提供更均匀的等待时间

<figure markdown="span">
  ![C-SCAN 磁盘调度](https://webp-pic.yokumi.cn/2025/12/20251220165127019.png){ loading=lazy width="70%" }
</figure>

### LOOK

- SCAN 的改进：磁头到达当前方向上**最后一个请求**后即反向，无需到达磁盘物理末端
- 减少不必要的磁头移动

<figure markdown="span">
  ![LOOK 磁盘调度](https://webp-pic.yokumi.cn/2025/12/20251220170017879.png){ loading=lazy width="70%" }
</figure>

### C-LOOK

- C-SCAN 的改进：磁头到达当前方向上**最后一个请求**后即返回起始端最近请求，无需到达磁盘物理端点
- 同样减少不必要的磁头移动

<figure markdown="span">
  ![C-LOOK 磁盘调度](https://webp-pic.yokumi.cn/2025/12/20251220170034169.png){ loading=lazy width="70%" }
</figure>

!!! abstract "调度算法选择"
    - 磁盘请求队列较短时，FCFS 和 SSTF 差异不大
    - 磁盘负载较重时，LOOK / C-LOOK 更优
    - C-LOOK 提供最均匀的响应时间，是实际系统中常用的选择

## 磁盘管理

### 磁盘格式化

| 阶段 | 操作 | 说明 |
| --- | --- | --- |
| 低级格式化 | 将磁盘划分为扇区 | 每个扇区包含数据区、头部、尾部（含 ECC 校验码） |
| 分区 | 将柱面划分为若干分区 | 每个分区可视为独立的逻辑磁盘 |
| 逻辑格式化 | 在分区上创建文件系统 | 写入文件系统数据结构（如超级块、空闲空间管理等） |

### 引导块

系统启动过程：

1. ROM 中的 **bootstrap loader** 执行
2. 从磁盘的**引导块（Boot Block）**中查找并加载完整的引导程序
3. 引导程序加载操作系统内核

<figure markdown="span">
  ![引导块](https://webp-pic.yokumi.cn/2025/12/20251220190049822.png){ loading=lazy width="70%" }
</figure>

!!! note "要点"
    - ROM 中仅存储 **bootstrap loader**（而非完整的引导程序），因为 ROM 不易更新
    - 引导块 = 磁盘上存储引导程序的块，可随 OS 更新而更新

### 坏块处理

- 通过 ECC 校验检测坏块
- 处理方式：**转发（Forward/重定向）**——将坏块映射到备用扇区，后续对坏块的访问自动重定向到备用扇区

## 交换空间管理

交换空间将磁盘空间作为内存的扩展，用于进程换入/换出。交换空间的实现位置：

| 方式 | 特点 |
| --- | --- |
| 普通文件系统 | 管理方便，但文件系统开销大、速度较慢 |
| 独立磁盘分区 | 避免文件系统开销，效率更高 |
| 独立裸分区 | 直接读写，最高效，但需自行管理空间 |
