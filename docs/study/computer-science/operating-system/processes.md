# 进程

## 进程的概念

进程
: 程序的一次执行过程。程序是静态的，进程是动态的。

进程映像（Process Image）包括：

- 程序计数器（PC）：记录当前执行到的指令位置
- 堆（Heap）：动态分配的内存
- 栈（Stack）：函数调用、局部变量
- 数据段（Data）：全局变量、静态变量
- 代码段（Text）：程序代码

!!! abstract "程序 vs 进程"
    程序是**静态的**可执行文件，存储在磁盘上；进程是**动态的**程序执行实例，存在于内存中。一个程序可以对应多个进程。

## 进程的状态

进程在其生命周期中会在以下五种状态之间转换：

| 状态 | 说明 |
|------|------|
| 新建（New） | 进程正在被创建 |
| 运行（Running） | 进程正在 CPU 上执行指令 |
| 就绪（Ready） | 进程已准备好执行，等待分配 CPU |
| 等待（Waiting） | 进程等待某个事件完成（如 I/O） |
| 终止（Terminated） | 进程执行完毕 |

!!! warning
    单处理器系统中，任一时刻最多只有一个进程处于 Running 状态。

主要的状态转换：

- New → Ready：进程创建完成，被接纳进入就绪队列
- Ready → Running：调度器选择该进程分配 CPU
- Running → Ready：时间片用完，被调度器抢占
- Running → Waiting：进程请求 I/O 或等待事件
- Waiting → Ready：I/O 完成或等待的事件发生
- Running → Terminated：进程执行完毕或被终止

## 进程控制块（PCB）

PCB（Process Control Block）
: 操作系统为每个进程维护的数据结构，记录了进程的全部管理信息，是进程存在的唯一标识。

PCB 中包含的信息：

- **进程标识（PID）**：唯一标识一个进程
- **进程状态**：当前所处的状态（new / ready / running / waiting / terminated）
- **程序计数器（PC）**：进程下一条要执行的指令地址
- **CPU 寄存器**：保存进程被中断时的寄存器内容，用于恢复执行
- **CPU 调度信息**：优先级、调度队列指针等
- **内存管理信息**：页表、段表、基址/限长寄存器等
- **I/O 状态信息**：分配的 I/O 设备、打开的文件列表等
- **记账信息**：CPU 时间使用量、时间限制等

## 上下文切换的触发

以下事件会触发上下文切换：

| 触发事件 | 说明 |
|----------|------|
| 时钟中断（Clock Interrupt） | 时间片用完，当前进程被抢占，切换到下一个就绪进程 |
| I/O 中断（I/O Interrupt） | I/O 操作完成，等待 I/O 的进程被唤醒，可能触发调度 |
| 内存故障（Memory Fault） | 如缺页中断（Page Fault），进程进入 Waiting 状态，等待页面换入后再回到 Ready |
| 陷阱（Trap） | 程序错误（如除零、非法访问），可能导致进程终止 |
| 系统调用（System Call） | 进程请求操作系统服务（如打开文件），可能进入 Waiting 等待服务完成 |

!!! note "内存故障的处理流程"
    Page Fault → 进程进入 Waiting → 操作系统将所需页面从磁盘换入内存 → I/O 完成 → 进程回到 Ready

## 进程调度

### 上下文切换（Context Switch）

上下文切换
: 操作系统保存当前进程的状态（存入其 PCB），并恢复下一个进程的状态（从其 PCB 读取），使其从上次中断的位置继续执行。

<figure markdown="span">
  ![进程调度示意图](https://webp-pic.yokumi.cn/2025/10/20251007180403092.png){ loading=lazy width="70%" }
</figure>

上下文切换的开销：

- 保存/恢复寄存器、PC、栈指针等
- 切换内存地址空间（页表基址等）
- 刷新 TLB 和 Cache
- 开销随切换频率的增加而增大

!!! warning
    上下文切换是纯开销，不执行任何有用的工作。频繁的上下文切换会显著降低系统吞吐量。

### 调度队列

作业队列（Job Queue）
: 包含系统中**所有进程**。进程进入系统时被加入此队列。

就绪队列（Ready Queue）
: 包含所有**处于就绪状态、等待 CPU 分配**的进程。通常以 PCB 链表形式组织，调度器从中选择进程执行。

设备队列（Device Queue）
: 每个 I/O 设备都有自己的设备队列，存放**等待该设备 I/O 操作完成**的进程。

### 调度器

| 调度器 | 频率 | 功能 |
|--------|------|------|
| 长期调度器（Long-term Scheduler）| 低 | 从作业队列中选择进程进入内存（就绪队列），控制多道程序度 |
| 短期调度器（Short-term Scheduler）| 高 | 从就绪队列中选择进程分配 CPU（即 CPU 调度器） |
| 中期调度器（Medium-term Scheduler）| 中 | 将进程换出（Swap out / Suspend）内存以降低多道程序度，后续可换入恢复 |

???+ info "中期调度器"
    中期调度器的核心功能是将进程在内存与磁盘之间换入换出（Swapping），以平衡系统负载。

    <figure markdown="span">
      ![中期调度示意图](https://webp-pic.yokumi.cn/2025/10/20251007182526541.png){ loading=lazy width="70%" }
    </figure>

!!! abstract "多道程序度（Degree of Multiprogramming）"
    长期调度器控制内存中的进程数量。过多进程会导致频繁换页（Thrashing），过少则 CPU 利用率低。

### I/O 密集型 vs CPU 密集型进程

I/O 密集型进程（I/O-bound）
: 大部分时间在等待 I/O 操作完成，CPU 执行时间短。应优先分配 CPU，以提高 I/O 设备利用率。

CPU 密集型进程（CPU-bound）
: 大部分时间在 CPU 上执行计算，I/O 请求少。应适当分配较长的时间片。

!!! note
    系统应保持 I/O-bound 和 CPU-bound 进程的合理搭配，以充分利用 CPU 和 I/O 设备。

## 进程操作

### 进程创建

进程可以创建其他进程，形成**进程树**：

- 创建者称为**父进程（Parent Process）**
- 被创建者称为**子进程（Child Process）**
- 父进程和子进程并发执行

#### 资源共享方式

父进程创建子进程时，资源共享有三种选择：

1. 父子进程共享所有资源
2. 子进程共享父进程资源的子集
3. 父子进程不共享资源，子进程获取系统资源

#### 执行模式

1. 父子进程并发执行
2. 父进程等待子进程终止后再执行

#### 地址空间

1. 子进程复制父进程的地址空间（写时复制，Copy-on-Write）
2. 子进程加载新的程序执行

### 进程终止

进程执行完最后一条语句后，由操作系统终止（正常终止）。也可能因错误或被其他进程终止（异常终止）。

<figure markdown="span">
  ![进程终止示意图](https://webp-pic.yokumi.cn/2025/10/20251008133801296.png){ loading=lazy width="70%" }
</figure>

进程终止的原因：

- 正常退出（自愿）
- 错误退出（自愿）
- 致命错误（被迫，如 Segmentation Fault）
- 被其他进程杀死（被迫）

!!! note "级联终止"
    在某些系统中，父进程终止时其所有子进程也会被终止（级联终止）。

## 进程间通信（IPC）

### 独立进程与协作进程

独立进程（Independent Process）
: 不受其他进程影响，也不影响其他进程。进程之间不共享数据。

协作进程（Cooperating Process）
: 可受其他进程影响或影响其他进程。进程之间共享数据，需要 IPC 机制。

进程协作的优势：

- 信息共享
- 加速计算（任务并行）
- 模块化

### IPC 的两种基本模型

| 模型 | 机制 | 特点 |
|------|------|------|
| 共享内存（Shared Memory） | 进程共享同一块内存区域 | 速度快，但需要同步机制 |
| 消息传递（Message Passing） | 通过 send/receive 交换消息 | 适用于分布式环境，无需共享内存 |

## 共享内存 —— 生产者-消费者问题

生产者和消费者通过共享的**有界缓冲区**进行通信：生产者向缓冲区写入数据，消费者从缓冲区读取数据。

### 有界缓冲区的环形表示

<figure markdown="span">
  ![生产者-消费者环形缓冲区](https://webp-pic.yokumi.cn/2025/10/20251008140736940.png){ loading=lazy width="70%" }
</figure>

- 缓冲区大小为 `BUFFER_SIZE`
- `in` 指针：生产者下一个写入位置
- `out` 指针：消费者下一个读取位置
- 缓冲区为空：`in == out`
- 缓冲区为满：`(in + 1) % BUFFER_SIZE == out`

!!! warning
    环形缓冲区最多只能存放 `BUFFER_SIZE - 1` 个项，需要牺牲一个位置来区分"满"和"空"的状态。

## 消息传递

消息传递提供 `send` 和 `receive` 两个原语（Primitive），二者不可中断。

### 通信方式

#### 直接通信

进程直接通过名字或标识符进行通信：

- `send(P, message)`：向进程 P 发送消息
- `receive(Q, message)`：从进程 Q 接收消息

特性：

- 通信链路自动建立
- 每个链路恰好关联一对进程
- 链路可以是单向的，但通常是双向的

#### 间接通信

通过**邮箱（Mailbox）**进行通信，邮箱有唯一标识符（ID）：

- `send(A, message)`：向邮箱 A 发送消息
- `receive(A, message)`：从邮箱 A 接收消息

特性：

- 共享同一邮箱的进程之间可以通信
- 一个邮箱可以被多个进程共享
- 链路可以在多于两个进程之间建立

!!! note
    共享邮箱的多个进程之间如何建立唯一链路，需要额外的同步机制来保证。

### 同步方式

| 方式 | send | receive |
|------|------|---------|
| 阻塞（Blocking / 同步） | 发送方阻塞直到消息被接收 | 接收方阻塞直到消息可用 |
| 非阻塞（Non-blocking / 异步） | 发送方发送后立即继续执行 | 接收方接收不到消息时立即返回 |

### 缓冲方式

| 缓冲容量 | 说明 |
|----------|------|
| 零容量（Zero Capacity） | 无缓冲，发送方必须阻塞等待接收方（即同步通信） |
| 有界容量（Bounded Capacity） | 队列长度有限；满时发送方阻塞，未满时非阻塞发送 |
| 无界容量（Unbounded Capacity） | 队列长度无限；发送方永远不需要阻塞 |

## 管道（Pipe）

管道是早期 UNIX 系统提供的 IPC 机制，本质上是一种特殊的有界缓冲区。

### 普通管道（Ordinary Pipe）

- 生产者-消费者模式：一个进程写入，另一个进程读取
- **单向**数据流
- 仅存在于**父子进程**之间
- 管道两端在进程创建时确定

### 命名管道（Named Pipe）

- **双向**数据流
- 不限于父子进程，通信范围更广
- 通过文件系统中的名称标识
- 多个进程可通过同一命名管道通信

!!! abstract "普通管道 vs 命名管道"
    普通管道适用于具有亲缘关系的进程间的单向通信；命名管道则支持无关进程间的双向通信，适用范围更广。
