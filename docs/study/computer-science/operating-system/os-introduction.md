# 操作系统引论

## 什么是操作系统

操作系统（Operating System, OS）
: 用户与硬件之间的中介（intermediary），是计算机系统中一组**系统软件**的集合

内核（Kernel）
: 操作系统中始终运行的核心部分，亦称**核心程序 / nucleus**

!!! quote "An Operating System is interrupt driven"
    操作系统是**中断驱动**的——没有中断，操作系统无法获得控制权。

## 计算机系统的组织

### 引导与中断

引导程序（Bootstrap program）
: 存放于 ROM / 固件（firmware）中的小程序，系统开机时执行，负责将 OS 内核从磁盘加载到内存并启动

!!! info "中断驱动的本质"
    - 系统启动后，OS 便依赖**中断**（interrupt）来获得 CPU 控制权
    - 中断类型：硬件中断（I/O 完成等）、软件中断（系统调用 trap / fault）
    - 中断发生时，CPU 保存当前上下文，转去执行对应的中断服务例程（ISR）

## 存储器层次结构

<figure markdown="span">
  ![存储器层次结构](https://webp-pic.yokumi.cn/2025/09/20250913202045622.png){ loading=lazy width="70%" }
</figure>

从上到下，速度递减、容量递增、成本递减：

| 层级 | 存储器 | 特点 |
|------|--------|------|
| 1 | 寄存器（Registers） | 最快、容量最小、CPU 内部 |
| 2 | 高速缓存（Cache） | SRAM，L1/L2/L3 |
| 3 | 主存（Main Memory） | DRAM，易失性 |
| 4 | 固态盘（SSD） | 非易失，比磁盘快 |
| 5 | 磁盘（Magnetic Disk） | 非易失，大容量 |
| 6 | 光盘（Optical Disk） | 非易失，只读/可写 |
| 7 | 磁带（Magnetic Tape） | 非易失，顺序访问，归档用 |

!!! abstract "核心思想"
    存储层次的设计目标是以合理成本获得接近最顶层存储器的速度和最底层存储器的容量，其基础是**程序局部性原理**（principle of locality）。

## I/O 结构

### 程序控制 I/O（Programmed I/O）

程序控制 I/O
: CPU 不断轮询（polling）I/O 设备状态寄存器，判断 I/O 是否完成

- CPU 全程等待，效率极低
- 适用于简单、低速设备

### 中断驱动 I/O（Interrupt-Driven I/O）

中断驱动 I/O
: CPU 发出 I/O 请求后不再轮询，I/O 完成时设备发中断通知 CPU

分为两种：

同步中断驱动 I/O
: CPU 发出请求后**阻塞等待**中断，I/O 完成后才继续执行

异步中断驱动 I/O
: CPU 发出请求后**继续执行其他任务**，I/O 完成后通过中断回调处理结果

### 直接存储器存取（DMA）

DMA（Direct Memory Access）
: I/O 设备与主存之间直接传送数据，无需 CPU 逐字干预；CPU 仅在传送开始和结束时介入

- 适用于**块设备**的大批量数据传输
- 每次传输以**块（block）** 为单位

### I/O 通道控制

I/O 通道（I/O Channel）
: 专用的 I/O 处理机，拥有自己的指令系统，可独立执行 I/O 程序

- 通道完成 I/O 后向 CPU 发中断
- 进一步解放 CPU，适用于大型机

## 计算机系统体系结构

### 单处理器系统

单处理器系统（Single-Processor System）
: 系统中只有一个通用 CPU，执行所有用户程序和 OS 功能

### 多处理器系统

多处理器系统（Multi-Processor System）
: 系统中有多个 CPU 共享主存和外设

SMP（对称多处理）
: 所有处理器地位平等，共享主存和 I/O，任一处理器均可运行 OS 和用户程序

ASMP（非对称多处理）
: 一个主处理器运行 OS，其余从处理器执行用户程序或特定任务

!!! tip "SMP vs ASMP"
    SMP 是当前主流多处理器架构；ASMP 因主处理器瓶颈问题，已较少使用。

### 多核系统

多核（Multi-Core）
: 单个芯片上集成多个处理器核心，本质上是 SMP 的一种紧凑实现形式

### 刀片服务器

刀片服务器（Blade Server）
: 将多个计算模块（blade）插入同一机架，共享电源、网络等资源，每个 blade 可独立运行 OS

### 集群系统

集群系统（Clustered System）
: 多台独立计算机通过高速网络互连，协同工作

- 可用于高可用性（HA）、负载均衡、并行计算
- 节点间通信通常走局域网

## 操作系统结构

### 单道程序设计（Uniprogramming）

单道程序设计
: 内存中仅有一道程序运行，CPU 在该程序等待 I/O 时空闲

!!! warning "CPU 利用率极低"
    单道程序设计的核心问题是 I/O 等待期间 CPU 完全空闲。解决方案包括：

脱机 I/O（Off-line I/O）
: I/O 操作在脱离主机控制的设备上进行，使用磁带作为中间介质

SPOONG（Simultaneous Peripheral Operations On-Line）
: 用磁盘代替磁带实现联机同时外围操作；I/O 数据先写入磁盘缓冲区，再由专门的 I/O 进程处理，使 CPU 不必等待慢速 I/O

### 多道程序设计（Multiprogramming）

多道程序设计
: 内存中同时驻留多道程序，当一道程序等待 I/O 时，CPU 切换到另一道程序执行

- 通过**作业调度（job scheduling）** 选择哪些作业进入内存
- 目标：提高 CPU 利用率，使 CPU 与 I/O 并行工作

### 分时系统（Time-Sharing）

分时系统
: 多个用户通过终端同时使用计算机，OS 以**时间片（time slice）** 为单位轮流为各用户服务

关键概念：

进程（Process）
: 程序的一次执行实例，是资源分配和调度的基本单位

CPU 调度（CPU Scheduling）
: 决定哪个进程获得 CPU 时间，需保证响应时间可接受

交换（Swapping）
: 将暂时不运行的进程换出到磁盘，腾出内存给其他进程

虚拟内存（Virtual Memory）
: 允许进程使用比物理内存更大的地址空间，部分内容驻留磁盘，按需调入

### 批处理系统 vs 分时系统

| 特征 | 批处理系统（Batch） | 分时系统（Time-Sharing） |
|------|---------------------|--------------------------|
| 目标 | 吞吐量最大化 | 响应时间最小化 |
| 用户交互 | 无 | 有，多终端 |
| 作业提交 | 批量提交 | 联机交互 |
| 调度 | 作业调度 | CPU 调度 + 作业调度 |
| 适用场景 | 科学计算、大数据处理 | 交互式开发、办公 |

## 双重模式操作

<figure markdown="span">
  ![双重模式操作](https://webp-pic.yokumi.cn/2025/09/20250913223349727.png){ loading=lazy width="70%" }
</figure>

用户态（User Mode）
: 受限运行模式，不能直接访问硬件和敏感指令；需要通过**系统调用（system call）** 请求 OS 服务

内核态（Kernel Mode）
: 完全特权模式，可执行所有指令、访问所有内存和硬件

!!! abstract "模式切换机制"
    - 系统调用（trap / syscall）、中断、异常（fault）发生时，CPU 从用户态切换到内核态
    - OS 处理完毕后，通过中断返回指令（iret 等）切回用户态
    - 模式位（mode bit）由硬件维护，用于标识当前运行模式

## 进程管理

进程（Process）
: 程序的执行实例，是操作系统进行资源分配和调度的基本单位

OS 的进程管理职责：

- 进程的创建与终止
- 进程的暂停与恢复
- 进程同步与进程间通信
- 进程调度（CPU 分配）
- 死锁处理

## 内存管理

OS 的内存管理职责：

- 跟踪内存的哪些部分正在被使用、被谁使用
- 内存分配与回收
- 内存保护：防止进程互相干扰
- 内存扩充：虚拟内存、页面置换

## 存储管理

### 一致性与连贯性

<figure markdown="span">
  ![一致性与连贯性](https://webp-pic.yokumi.cn/2025/09/20250921152539562.png){ loading=lazy width="70%" }
</figure>

一致性（Coherency）
: 同一数据的多个副本在不同存储层级（如 cache 与主存）之间保持值相同

连贯性（Consistency）
: 数据在被修改后，所有相关副本最终都能反映最新值；涉及**更新策略**（写直达 / 写回等）

!!! warning "分布式系统中的一致性问题"
    在多处理器 / 分布式环境中，coherency 与 consistency 问题更加突出，需要硬件协议（如 MESI）和软件机制共同保证。

### I/O 子系统

OS 的 I/O 子系统提供统一的 I/O 接口，屏蔽设备差异，主要技术包括：

缓冲（Buffering）
: 在内存中设置缓冲区，缓解 CPU 与 I/O 设备之间的速度差异

缓存（Caching）
: 将频繁访问的数据副本保留在高速存储中，减少对慢速设备的访问

SPOONG
: 同时联机外围操作，详见[单道程序设计](#_7)一节

## 保护与安全

保护（Protection）
: 控制进程对系统资源的访问权限，防止进程间相互干扰

安全（Security）
: 防止外部攻击者对系统的未授权访问和破坏

核心机制：

- 访问控制：权限矩阵、ACL、能力列表
- 身份认证：口令、令牌、生物识别
- 审计：记录安全相关事件

## 分布式系统

网络操作系统（Network OS）
: 节点各自运行独立 OS，通过网络协议通信；节点间松耦合，用户感知到的是多个独立系统

分布式操作系统（Distributed OS）
: 用户看到的是一个统一系统，OS 在全局范围内调度资源；节点间紧耦合

???+ info "网络 OS 与分布式 OS 的关键区别"
    | 特征 | 网络 OS | 分布式 OS |
    |------|---------|-----------|
    | 耦合度 | 松耦合 | 紧耦合 |
    | 全局调度 | 无 | 有 |
    | 进程迁移 | 不支持 | 支持 |
    | 用户感知 | 多个独立系统 | 单一系统 |
    | 文件系统 | 各自独立 | 全局统一 |

    **进程迁移（Process Migration）** 是分布式 OS 的重要特性：可将进程从一个节点迁移到另一个节点执行，以实现负载均衡。
