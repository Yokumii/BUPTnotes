# 虚拟内存

## 请求调页（Demand Paging）

请求调页与传统的 Swap 机制不同：Swap 在进程启动时将整个进程调入内存，而请求调页采用**懒加载（Lazy Swapper）**策略——仅在页面被实际访问时才将其调入内存，即"按需"调页。

### 有效-无效位

每个页表项（PTE）中设有一个**有效-无效位（Valid-Invalid Bit）**：

| 位值 | 含义 |
| --- | --- |
| 1（Valid） | 该页在内存中 |
| 0（Invalid） | 该页不在内存中 |

当进程访问有效-无效位为 0 的页面时，触发**缺页中断（Page Fault）**。

!!! abstract "Swap vs Demand Paging"
    - **Swap**：将整个进程换入/换出内存，启动时全部加载
    - **Demand Paging**：仅在实际访问页面时才加载，减少不必要的 I/O 和内存占用

## 缺页中断处理流程

<figure markdown="span">
  ![缺页中断处理流程](https://webp-pic.yokumi.cn/2025/12/20251221130404797.png){ loading=lazy width="70%" }
</figure>

处理步骤：

1. CPU 访问某页面，检查有效-无效位
2. 若位为 **i（Invalid）**，产生 trap 陷入内核
3. OS 检查该访问是否合法：
    - **非法访问**（如越界）→ 终止进程（Abort）
    - **合法但不在内存中** → 继续
4. 查找空闲帧，若无空闲帧则执行**页面置换**
5. 从磁盘读取所需页面到空闲帧
6. 更新页表，将有效-无效位置为 **1（Valid）**
7. 重新执行引发缺页中断的那条指令

!!! warning
    缺页中断处理完成后，必须**重新执行**引发中断的指令，而非跳过。

## 写时复制（Copy-on-Write）

`fork()` 创建子进程时，并不立即复制父进程的全部物理页面，而是让父子进程**共享同一组物理页面**，并将这些页面标记为**只读**。

当任一进程尝试**写入**某页面时：

1. 写操作触发保护异常（Protection Fault）
2. OS 捕获异常，为该进程**复制一份该页面的副本**
3. 副本标记为可读写，原页面恢复适当的权限
4. 进程在各自的副本上继续执行

!!! abstract "写时复制的优势"
    - 只有被**修改**的页面才会被复制，未修改的页面始终共享
    - 显著减少 `fork()` 的时间和内存开销
    - 若子进程立即调用 `exec()`，则几乎不需要复制任何页面

## 页面置换算法

当没有空闲帧可用时，必须选择一个已在内存中的页面换出，以腾出空间装入新页面。不同的置换策略直接影响缺页率。

### FIFO（先进先出）

- 替换**最先进入内存**的页面（即驻留时间最长的页面）
- 实现简单，维护一个 FIFO 队列即可
- 可能出现 **Belady 异常**：增加物理帧数反而导致缺页次数增加

???+ warning "Belady 异常"
    FIFO 是唯一可能产生 Belady 异常的常用算法。例如，对于引用串 1,2,3,4,1,2,5,1,2,3,4,5，3 个帧的缺页次数为 9，而 4 个帧的缺页次数反而为 10。

### OPT（最优置换）

- 替换**将来最长时间内不会被使用**的页面
- 缺页率最低，不会产生 Belady 异常
- **无法实现**（需要未来信息），仅作为**理论基准（Benchmark）**用于评估其他算法
- OPT 在正序和逆序引用串上的缺页率一致

### LRU（最近最少使用）

- 替换**最长时间未被访问**的页面
- 基于**局部性原理**：最近被访问的页面很可能在不久后再次被访问
- 性能接近 OPT，不会产生 Belady 异常
- 正序和逆序引用串上的缺页率一致
- 实现较复杂，常见方式：

    | 实现方式 | 说明 |
    | --- | --- |
    | 计数器法（Counter） | 每个页表项关联时间戳，每次访问更新；置换时选择时间戳最小的页面 |
    | 栈法（Stack） | 维护一个按访问时间排序的栈；每次访问将页面移至栈顶；置换时选择栈底页面 |

!!! abstract "LRU vs OPT"
    LRU 基于"过去"的访问信息做决策，OPT 基于"未来"的访问信息做决策。由于局部性原理，LRU 在实际中表现接近 OPT。

### 二次机会算法（Second Chance / Clock）

- 基于 FIFO + **引用位（Reference Bit）**的改进算法
- 页面组织为环形队列（类似时钟），每页关联一个引用位

扫描过程：

1. 检查当前页面的引用位
2. 若引用位 = **1**：清零，跳过，继续扫描下一个页面
3. 若引用位 = **0**：替换该页面
4. 若所有页面的引用位均为 1，则一轮扫描后全部清零，回到起点替换第一个页面

!!! note
    二次机会算法的本质是：给每个页面"第二次机会"——如果近期被访问过（引用位=1），则暂时不替换，但清零引用位；若再次扫描到仍为 0，说明之后没有再被访问，可以替换。

### 算法对比

| 算法 | 置换依据 | Belady 异常 | 可实现性 | 性能 |
| --- | --- | --- | --- | --- |
| FIFO | 驻留时间最长 | 可能 | 简单 | 较差 |
| OPT | 未来最久不用 | 不会 | 不可实现（基准） | 最优 |
| LRU | 过去最久未用 | 不会 | 复杂 | 接近 OPT |
| Second Chance | FIFO + 引用位 | 可能 | 中等 | FIFO 改进 |

## 帧分配

每个进程需要一定数量的物理帧，最少帧数取决于指令格式、操作数个数和间接寻址方式。

### 分配策略

| 策略 | 说明 |
| --- | --- |
| 固定分配（Equal） | 所有进程分配相同数量的帧 |
| 固定分配（Proportional） | 按进程大小比例分配帧数 |
| 优先级分配（Priority） | 按进程优先级动态分配，高优先级进程可获得更多帧 |

### 置换范围

| 置换方式 | 说明 |
| --- | --- |
| 局部置换（Local Replacement） | 仅在本进程已分配的帧中选择替换 |
| 全局置换（Global Replacement） | 可从所有进程的帧中选择替换 |

分配策略与置换范围的对应关系：

- **固定分配** → 只能使用**局部置换**（帧数固定，不能抢占其他进程的帧）
- **优先级分配** → 可使用**局部置换**或**全局置换**
- **全局置换**通常比局部置换更高效（灵活性强，可动态调整）

## 抖动（Thrashing）

当系统中进程过多、每个进程分配的帧数不足时：

1. 每个进程频繁发生缺页中断
2. 不断进行页面置换，但刚换入的页面很快又被换出
3. CPU 利用率急剧下降（大部分时间在等待页面 I/O）
4. OS 误以为 CPU 利用率低是因为进程数不够，继续增加进程
5. 情况进一步恶化，形成恶性循环

!!! warning "抖动的根本原因"
    抖动的根本原因是：系统中所有进程的**工作集总大小超过了可用物理内存**。此时无论怎样置换页面都无法满足需求。

## 工作集模型（Working-Set Model）

工作集模型用于跟踪进程的局部性，为帧分配提供依据。

- **工作集窗口 Δ**：考察最近的 Δ 次页面访问
- **工作集 WSS_i**：进程 i 在窗口 Δ 内访问的**不同页面数**
- **系统总需求**：ΣWSS_i 表示所有进程的工作集大小之和

判定条件：

| 条件 | 结果 |
| --- | --- |
| ΣWSS_i ≤ 可用内存 | 不会抖动，各进程有足够帧 |
| ΣWSS_i > 可用内存 | 发生抖动，需要挂起部分进程 |

???+ info "窗口大小 Δ 的选择"
    - Δ 过小：无法覆盖完整的局部性，工作集估计不足
    - Δ 过大：包含多个局部性，工作集过大，内存浪费
    - Δ 必须选择适当，使工作集能准确反映进程当前的局部性
