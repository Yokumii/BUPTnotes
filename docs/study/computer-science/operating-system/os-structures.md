# 操作系统结构

## 操作系统服务

操作系统为用户和程序提供一系列服务，可分为面向用户的服务与面向资源管理的服务。

### 面向用户的服务

用户界面
: 操作系统为用户提供与系统交互的方式，主要有三种形式：

    - 命令行界面（CLI）：用户通过键盘输入命令
    - 批处理界面（Batch）：将命令写入文件，由系统批量执行
    - 图形用户界面（GUI）：通过窗口、图标、菜单等图形元素与系统交互

程序执行
: 系统必须能把程序装入内存并运行，程序还需能正常或异常终止

I/O 操作
: 程序运行时可能需要 I/O，操作系统提供统一的 I/O 接口，使程序无需关心设备细节

文件系统操作
: 程序需要读写文件和目录，创建/删除文件，搜索文件，列出文件信息，以及管理文件权限

通信
: 进程间交换信息，主要有两种方式：

    - 共享内存（Shared Memory）：两个或多个进程共享同一块内存区域
    - 消息传递（Message Passing）：进程通过操作系统提供的通信机制传递消息

错误检测
: 操作系统需要持续检测可能的错误，包括 I/O 错误、内存错误、设备故障、用户程序错误等。对每类错误，操作系统应采取适当措施以保证一致性的计算

### 面向资源的服务

资源分配
: 多用户/多任务环境下，操作系统需要管理 CPU 时间、内存、文件存储、I/O 设备等资源。对 CPU 调度、I/O 设备分配等采用不同策略

记账
: 记录用户使用的资源数量，用于统计和计费

保护与安全
: 控制对系统资源的访问，确保资源仅被授权用户/进程访问。包括身份认证和访问控制

## 用户与操作系统接口

### 命令解释程序

命令解释程序（Command Interpreter，即 CLI/Shell）是用户与操作系统之间的接口。用户通过输入命令来请求操作系统执行操作。

命令解释程序获取命令的主要方式：

- 命令解释程序本身包含执行命令的代码
- 通过系统程序实现命令功能，命令解释程序仅负责查找并执行对应的程序

### 图形用户界面

GUI 提供更直观的用户交互方式，通过窗口、图标、菜单和指针（WIMP）等元素让用户操作计算机。

## 系统调用

系统调用是操作系统提供给程序的编程接口，程序通过系统调用请求操作系统的服务。

  ![系统调用接口](https://webp-pic.yokumi.cn/2025/09/20250922202951826.png){ loading=lazy width="70%" }
</figure>

### 为什么通过 API 访问系统调用

程序通常通过 API（如 POSIX API、Win32 API、Java API）而非直接使用系统调用，原因：

- **可移植性**：API 在不同操作系统上提供一致的接口，程序无需为每个系统单独编写
- **易用性**：API 封装了系统调用的细节，使用更方便

### 系统调用的实现

运行时支持库（run-time support）提供了系统调用接口，它充当用户程序与操作系统之间的桥梁。当程序调用 API 函数时，运行时库将请求转换为对应的系统调用，并触发陷入（trap）进入内核态执行。

### 参数传递

系统调用需要向操作系统传递参数，主要有三种方式：

寄存器传递
: 将参数直接存入 CPU 寄存器中。简单高效，但受寄存器数量限制

内存块传递
: 将参数存放在内存的块/表中，将块的地址通过寄存器传递给操作系统

栈传递
: 将参数压入用户栈，操作系统从栈中弹出参数

## 系统调用的类型

### 进程控制

- 创建/终止进程
- 装入/执行程序
- 获取/设置进程属性
- 等待事件/信号

### 文件管理

- 创建/删除文件
- 打开/关闭文件
- 读写文件
- 获取/设置文件属性

### 设备管理

- 请求/释放设备
- 读/写/重定位设备
- 获取/设置设备属性

### 信息维护

- 获取/设置系统时间与日期
- 获取/设置系统数据（如进程、文件、设备的属性）
- 获取/设置操作系统信息

### 通信

消息传递模型
: 进程通过消息队列交换消息，操作系统负责消息的缓冲和传递

共享内存模型
: 两个或多个进程共享一块内存区域，通过读写该区域进行通信；操作系统负责建立共享内存区域

### 保护

- 设置/获取文件权限
- 允许/拒绝访问资源
- 获取/设置安全上下文

## 系统程序

系统程序不是内核的一部分，而是运行在操作系统之上的程序，为用户和程序提供便利的环境。常见的系统程序包括：

- 文件管理程序（复制、删除、移动等）
- 状态信息程序（日期、时间、内存使用等）
- 程序设计支持（编译器、调试器等）
- 通信程序（邮件、网络浏览等）

!!! tip "系统程序 vs 系统调用"
    系统调用是操作系统内核提供的接口；系统程序是运行在用户态的程序，它们通常通过系统调用实现功能。

## 操作系统结构

### MS-DOS

MS-DOS 采用简单的单体结构，没有模块化分离。所有功能紧密耦合在一起，任何部分都可以直接访问其他部分和硬件。

</figure>

### 原始 UNIX

原始 UNIX 由内核和系统程序两大部分组成。内核包含文件系统、CPU 调度、内存管理等功能，系统程序运行在内核之上。

<figure markdown="span">
  ![原始 UNIX 结构](https://webp-pic.yokumi.cn/2025/09/20250924083543975.png){ loading=lazy width="70%" }
</figure>

### 分层法

分层法将操作系统分为若干层，每层仅使用其下层提供的功能和服务。

- **优点**：构造和调试简化，每层只需关心下层的接口
- **缺点**：难以合理定义各层边界；层间调用开销可能影响性能

### 微内核

微内核架构将内核精简到最基本的功能（进程间通信、基本调度、基本内存管理），而将大部分操作系统服务（文件系统、设备驱动等）放到用户态以服务进程的形式运行，通过消息传递进行通信。

- **优点**：灵活、可扩展、易于移植；服务进程之间相互隔离，一个服务崩溃不会影响其他服务
- **缺点**：频繁的消息传递带来性能开销

### 模块

模块架构使用可加载内核模块（Loadable Kernel Module）。内核提供核心功能，其他功能以模块形式在需要时动态加载到内核中。Linux 采用此结构。

<figure markdown="span">
  ![模块结构](https://webp-pic.yokumi.cn/2025/09/20250924084456108.png){ loading=lazy width="70%" }
</figure>

- **优点**：内核各部分可动态加载/卸载，灵活且性能较好（模块运行在内核态，无需消息传递）
- **缺点**：模块间接口需精心设计，否则可能产生安全或稳定性问题

### 混合系统

大多数现代操作系统并非严格采用某一种结构，而是混合多种方法。例如 Linux 本质上是单体结构，但支持可加载模块；Windows 采用混合内核结构。

## 虚拟机

虚拟机通过 CPU 调度和虚拟内存技术，为每个进程创造拥有独立处理器和内存的假象。

<figure markdown="span">
  ![虚拟机结构](https://webp-pic.yokumi.cn/2025/09/20250924090103543.png){ loading=lazy width="70%" }
</figure>

### 虚拟机的优点

- **完全保护**：每个虚拟机与底层硬件完全隔离，提供最高级别的安全保护
- **适合操作系统研究**：可以在虚拟机上安全地开发和调试操作系统，无需专用硬件
- **兼容性**：可以在同一物理机上运行不同类型的操作系统

### 虚拟机的缺点

- **双模式实现困难**：虚拟机自身运行在用户态，但客户操作系统需要执行内核态操作，这需要虚拟机管理器（VMM）来模拟特权指令，实现复杂

## 操作系统生成

操作系统生成（SYSGEN）是指根据特定硬件配置生成操作系统的过程。SYSGEN 程序获取硬件配置信息（CPU 类型、内存大小、设备类型等），然后通过以下方法之一生成操作系统：

修改源代码
: 根据硬件配置修改操作系统源代码，然后重新编译。最灵活但最耗时

从预编译库中选择
: 根据硬件配置从预编译的程序库中选择所需的模块进行链接。速度快但灵活性较低

表驱动
: 操作系统使用配置表描述硬件，运行时根据表的内容进行适配。最灵活，不需要重新编译或链接

## 系统启动

启动（booting）是指将操作系统内核装入内存并开始执行的过程。

现代系统的启动流程：

1. **ROM 中的引导装入程序**：开机后，CPU 首先执行存储在 ROM 中的小型引导装入程序（bootstrap loader）
2. **加载引导程序**：引导装入程序从磁盘的引导块（boot block）中读取并加载引导程序（boot program）
3. **加载操作系统**：引导程序从磁盘加载整个操作系统内核到内存，然后将控制权转交给操作系统

!!! info "引导块"
    引导块是磁盘上的一个特殊区域，存放引导程序。包含引导块的磁盘称为启动盘（boot disk）或系统盘（system disk）。
