# 内存管理

## 概述

CPU 只能直接访问**主存**和**寄存器**：

| 存储层次 | 访问速度 | 说明 |
| --- | --- | --- |
| 寄存器 | < 1 CPU 周期 | 最快，容量极小 |
| 主存 | 多个 CPU 周期 | 较慢，CPU 需等待（stall） |
| 缓存（Cache） | 介于两者之间 | 位于寄存器与主存之间，缓解速度差异 |

!!! tip "核心矛盾"
    CPU 速度远快于主存，直接访问主存会导致 CPU 停滞等待（stall）。Cache 的引入正是为了弥合这一速度鸿沟。

## 基址与限长寄存器

每个进程的合法物理地址范围由一对寄存器保护：

| 寄存器 | 含义 |
| --- | --- |
| **基址寄存器（Base）** | 最小合法物理地址 |
| **限长寄存器（Limit）** | 地址范围的大小 |

- 合法地址范围：`base` ~ `base + limit`
- CPU 产生的每次地址都会与这对寄存器比较，越界则触发陷阱（trap）
- 只有特权指令才能修改基址和限长寄存器

## 逻辑地址与物理地址

| 概念 | 别称 | 产生者 | 可见性 |
| --- | --- | --- | --- |
| 逻辑地址 | 虚拟地址 | CPU 生成 | 用户/程序可见 |
| 物理地址 | — | 内存单元 | 内存硬件可见，用户不可见 |

- **MMU（内存管理单元）**：在执行时将逻辑地址映射为物理地址
- **重定位寄存器方案**：物理地址 = 逻辑地址 + 重定位寄存器值

!!! abstract "重定位寄存器与基址寄存器"
    重定位寄存器本质上就是基址寄存器——两者都是将逻辑地址偏移到一个物理起点上。术语不同是因为侧重点不同：重定位强调"地址变换"，基址强调"地址保护"。

## 交换（Swapping）

将进程在内存与磁盘之间换入/换出，以腾出内存空间。

- 只有**完全空闲**的进程（处于就绪或等待状态）才能被换出
- 换入时需重新分配内存，地址通过重定位寄存器动态映射

???+ warning "挂起 I/O 问题"
    正在等待 I/O 完成的进程**不应被换出**，否则 I/O 操作会在错误的地址空间中执行，导致数据错乱。解决方案：

    - I/O 操作只使用内核缓冲区（而非用户空间），换出时先将 I/O 数据拷贝到内核空间
    - 或禁止换出有挂起 I/O 的进程

## 连续内存分配

- OS 占据低地址区域，用户进程占据高地址区域
- 每个进程配有一对**重定位/基址寄存器** + **限长寄存器**

### 动态分区（MVT）

- **空洞（Hole）**：空闲的内存块
- PCB 跟踪已分配分区和空闲分区
- 分区大小按进程实际需求动态分配

### 外部碎片与内部碎片

| 碎片类型 | 定义 | 产生原因 |
| --- | --- | --- |
| **外部碎片** | 总空闲空间足够，但分散为多个小空洞，无法满足大请求 | 动态分区分配与释放导致空闲空间不连续 |
| **内部碎片** | 分配给进程的空间大于实际需求，多余部分无法利用 | 分配单位大于实际需求 |

### 紧凑（Compaction）

移动进程使空闲空间合并为一个大的连续空洞。

- 代价高，需要重定位所有受影响的进程
- 只在动态重定位（运行时映射）时才可行

### 分配策略

| 策略 | 原则 | 特点 |
| --- | --- | --- |
| **首次适配（First-Fit）** | 按地址顺序找到第一个够大的空洞 | 速度快，低地址端产生大量小碎片 |
| **最佳适配（Best-Fit）** | 找到大小最接近需求的空洞 | 碎片最多（产生很多极小空洞），速度慢 |
| **最差适配（Worst-Fit）** | 找到最大的空洞 | 效果最差，大空洞被迅速耗尽 |

!!! note "结论"
    First-Fit 和 Best-Fit 在时间和空间效率上均优于 Worst-Fit。First-Fit 通常是最实用的选择。

## 分页（Paging）

分页消除了外部碎片，但**内部碎片仍然存在**（最后一页可能未填满）。

| 概念 | 对应空间 | 说明 |
| --- | --- | --- |
| **页帧（Frame）** | 物理内存 | 物理内存划分为固定大小的帧 |
| **页（Page）** | 逻辑地址空间 | 逻辑地址空间划分为固定大小的页 |
| **块（Block）** | 后备存储 | 磁盘上对应页大小的块 |

所有帧、页、块大小相同。

### 地址映射

逻辑地址由两部分组成：

$$\text{逻辑地址} = (\text{页号 } p,\ \text{页内偏移 } d)$$

- 通过**页表**将页号 $p$ 映射为帧号 $f$
- 物理地址 = 帧基址 + 偏移 $d$

### TLB（Translation Lookaside Buffer）

TLB 是页表的高速缓存，用于加速地址变换。

<figure markdown="span">
  ![TLB 地址变换](https://webp-pic.yokumi.cn/2025/12/20251221111834643.png){ loading=lazy width="70%" }
</figure>

**有效访问时间（EAT）**计算：

$$\text{EAT} = (\text{查表} + \text{访存}) \times h + (\text{查表} + \text{查页表} + \text{访存}) \times (1 - h)$$

其中 $h$ 为命中率（hit ratio）。

!!! example "EAT 计算示例"
    假设：查 TLB = 0ns，访存 = 100ns，查页表 = 100ns，命中率 = 80%

    $$\text{EAT} = (0 + 100) \times 0.8 + (0 + 100 + 100) \times 0.2 = 80 + 40 = 120\text{ns}$$

### 页表结构

#### 多级页表

将页表本身分页，形成层次结构。只有实际需要的页表页才驻留内存，节省空间。

两级地址映射过程：

!!! abstract "多级页表的权衡"
    - 优点：不需要将整个页表常驻内存，节省空间
    - 缺点：每增加一级就多一次内存访问，地址变换变慢

#### 哈希页表

虚拟页号经哈希函数映射到哈希表，冲突时通过链表遍历查找。

<figure markdown="span">
  ![哈希页表](https://webp-pic.yokumi.cn/2025/12/20251221123555593.png){ loading=lazy width="70%" }
</figure>

- 适用于地址空间很大（64 位）的场景
- 链表过长时查找效率下降

#### 反置页表

每个**物理帧**对应一个表项（而非每个逻辑页），节省空间。

<figure markdown="span">
  ![反置页表](https://webp-pic.yokumi.cn/2025/12/20251221123731457.png){ loading=lazy width="70%" }
</figure>

- 表项数 = 物理帧数，与进程数无关
- 缺点：查找时需要遍历整个表或借助哈希，速度较慢
