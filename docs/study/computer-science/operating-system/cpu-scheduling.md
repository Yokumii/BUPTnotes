# CPU 调度

## 调度类型回顾

| 调度类型 | 别称 | 频率 | 主要功能 |
| --- | --- | --- | --- |
| 长程调度 | 作业调度 | 低 | 控制多道程序度（调入进程） |
| 中程调度 | — | 中 | 内存管理（换入/换出） |
| 短程调度 | CPU 调度 | 高 | 就绪队列 → 分配 CPU，要求快速响应 |
| I/O 调度 | — | — | I/O 设备分配 |

## CPU 调度概述

CPU 调度发生在以下状态转换场景：

- **运行 → 终止**：进程执行完毕
- **运行 → 等待**：进程主动等待 I/O 等事件（非抢占/自愿）
- **运行 → 就绪**：时间片用完或被更高优先级抢占（抢占/强制）
- **等待 → 就绪**：I/O 完成，被外部事件唤醒（抢占/强制）

!!! abstract "非抢占 vs 抢占"
    - **非抢占（Nonpreemptive）**：只有运行进程主动放弃 CPU 时才发生调度（自愿让出）
    - **抢占（Preemptive）**：即使运行进程未主动放弃，也可由外部事件强制剥夺 CPU（如时间片耗尽、更高优先级进程就绪）

## 调度准则

| 准则 | 说明 |
| --- | --- |
| CPU 利用率 | CPU 忙碌时间的比例，通常目标 40%–90% |
| 吞吐量 | 单位时间内完成的作业数 |
| 周转时间 | 从进程创建到终止的总时间 |
| 等待时间 | 进程在就绪队列中等待的总时间 |
| 响应时间 | 从进程创建到首次运行的时间 |

!!! tip "核心公式"
    等待时间 + 突发时间 = 周转时间

    即：$$\text{Waiting Time} + \text{Burst Time} = \text{Turnaround Time}$$

## 调度算法

### FCFS（先来先服务）

- **非抢占式**，采用 FIFO 队列
- 有利于长作业，短作业受害（**护航效应/Convoy Effect**）
- 护航效应：所有其他进程等待一个大进程释放 CPU，导致平均等待时间增大

### SJF（最短作业优先）

- **非抢占式**（默认）：选择突发时间最短的进程
- **抢占式**变体为 **SRTF**（最短剩余时间优先，Shortest Remaining Time First）：当新进程到达时，若其突发时间 < 当前运行进程的剩余时间，则抢占
- SJF 拥有**最小的平均等待时间**（可证明）

???+ warning "SJF 的难点"
    实际中无法预知下一个 CPU 突发时间长度，只能通过历史数据进行**预测**（指数平均）。

### 优先级调度

- 可为**抢占式**或**非抢占式**
- 每个进程有优先级，优先选择优先级最高的进程
- **饥饿问题**：低优先级进程可能长期得不到执行
- **老化（Aging）**：随时间推移动态提高等待进程的优先级，解决饥饿

### RR（时间片轮转）

- **抢占式**，基于时间片（Time Quantum）
- 进程每次运行不能超过一个时间片；若突发时间 < 时间片，则执行完毕后立即切换
- 时间片大小的权衡：

    | 时间片 | 影响 |
    | --- | --- |
    | 过大 | 上下文切换少，但响应性差；极端情况退化为 FCFS |
    | 过小 | 响应性好，但上下文切换开销大 |

???+ info "时间片选择"
    时间片通常选在 10–100 ms 之间，需在响应时间和上下文切换开销之间取得平衡。

### 多级队列调度

- 将就绪队列划分为多个独立队列，不同队列使用不同算法
- 典型划分：

    | 队列类型 | 特点 | 常用算法 |
    | --- | --- | --- |
    | 前台队列（交互型） | 需要快速响应 | RR |
    | 后台队列（批处理型） | 不需要快速响应 | FCFS |

- 队列间调度策略：固定优先级（前台优先）或时间片分配

### 多级反馈队列调度

- 进程可以在不同队列之间**移动**
- 实现了 **老化机制**：长时间等待的进程可被提升到更高优先级队列
- 由以下参数定义：

    1. 队列数量
    2. 每个队列的调度算法
    3. 升级规则（何时提升到更高优先级队列）
    4. 降级规则（何时降低到更低优先级队列）
    5. 入口队列规则（新进程进入哪个队列）

!!! abstract "多级反馈队列的优势"
    多级反馈队列是最通用的 CPU 调度算法，既能照顾短作业/交互型进程的响应性，又能通过队列迁移防止长作业饥饿。

## 多处理器调度

| 类型 | 特点 | 问题 |
| --- | --- | --- |
| 非对称多处理（Asymmetric） | 主/从结构，仅主处理器执行 OS 代码和调度 | 主处理器成为瓶颈 |
| 对称多处理（SMP） | 所有处理器平等，均可执行 OS 功能 | 需要同步，负载均衡更复杂 |

## 线程调度

| 调度范围 | 别称 | 调度者 | 映射关系 | 模型 |
| --- | --- | --- | --- | --- |
| PCS（Process-Contention Scope） | 局部调度 | 线程库决定用户线程 → LWP 的映射 | m:1 / m:n | 多对一 / 多对多 |
| SCS（System-Contention Scope） | 全局调度 | 内核决定内核线程 → CPU 的映射 | 1:1 | 一对一 |

???+ info "PCS 与 SCS 的关系"
    - PCS 在用户空间完成，线程库将用户线程调度到可用的 LWP 上
    - SCS 由内核完成，将内核线程调度到 CPU 上执行
    - 在 1:1 模型下，每个用户线程对应一个内核线程，PCS 和 SCS 本质上合二为一
