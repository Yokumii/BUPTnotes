# 异常控制流

## 控制流与异常

程序计数器 PC 在处理器运行时不断读取指令序列的地址，两个指令间的过渡被称为**控制转移**，该指令序列被称为**控制流**，其中包含一些平滑的突变（即两条指令之间不相邻，如函数调用）。

异常控制流（ECF）
: 指令地址在控制流中发生突变时系统的反应。系统通过对突变做出反应，将这种突变称为异常控制流。

## 异常处理

### 概述

当有事件发生时，会通过一个跳转表（被称为**异常表**，每个异常编号对应一个索引存储的条目的地址），进行一个间接过程的调用（异常），转移控制给异常处理程序。当异常处理程序处理完成后，根据异常的类型，有以下三种结果：

- 返回控制给 $I_{cur}$（当前指令）
- 返回控制给 $I_{next}$（下一条指令）
- 终止被中断的程序

异常控制使得控制从用户态转移到内核态，被压入内核栈中。

## 异常类型

异常包含以下几种类型：

| 类型 | 同步/异步 | 说明 |
| ---- | ---- | ---- |
| 中断（Interrupts） | 异步（Asynchronous） | 由外部事件引起 |
| 陷阱（Traps） | 同步（Synchronous） | 故意执行的异常 |
| 故障（Faults） | 同步（Synchronous） | 由错误情况引起 |
| 终止（Aborts） | 同步（Synchronous） | 不可恢复的致命错误 |

### 中断

由外部事件引起，并非专门的指令造成的，比如 Timer interrupt（看门狗中断）、I/O interrupt。

!!! note
    中断是唯一一种**异步**异常，其余三种异常都是**同步**的。

### 陷阱

故意执行的异常，**在用户程序和内核之间提供一个接口，称为系统调用（System Calls）**。执行完后返回 $I_{next}$ 继续执行。

### 故障

由错误情况引起，将控制转移给故障处理程序，比如**缺页异常（可修复的）**。执行完后返回 $I_{cur}$ 继续执行或者终止。

!!! example "缺页异常（可修复）"
    <figure markdown="span">
      ![缺页异常可修复示例](https://webp-pic.yokumi.cn/2026/01/20260101164527734.png){ loading=lazy width="70%" }
    </figure>

    当执行到该指令时，`a[500]` 存放在磁盘中，需要从磁盘加载到内存中，此时触发故障。故障处理程序将缺失的地址送到内存后，返回 $I_{cur}$ 重新执行，此时能正确加载数据。

!!! example "段错误（不可修复）"
    <figure markdown="span">
      ![段错误示例](https://webp-pic.yokumi.cn/2026/01/20260101164532567.png){ loading=lazy width="70%" }
    </figure>

### 终止

由不可恢复的致命错误引起，终止被中断的程序。

## Linux 系统调用

!!! warning "系统调用表 vs 异常表"
    系统调用表和异常表**不是同一个东西**！系统调用表是系统调用的跳转表，异常表是异常处理的跳转表。
