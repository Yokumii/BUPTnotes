    查找

    顺序查找

    顺序查找（Sequential Search）从表的一端开始逐个比较关键字，直到找到目标或扫描完整个表。

    监视哨

    在查找前将待查关键字存入 ST.elem[0]，作为监视哨（哨兵）。这样在从后往前扫描时无需判断下标是否越界，当扫描到位置 0 时必然匹配哨兵，查找自动终止。

    监视哨的好处
    无需进行边界检测，提高查找效率。

    平均查找长度 ASL

    成功 ASL
    \(\frac{1+2+\cdots+n}{n} = \frac{n+1}{2}\)
    失败 ASL
    \(n+1\)（需要比较 \(n\) 个元素再加上哨兵位置的比较）

    折半查找

    折半查找（Binary Search）仅适用于有序顺序表，通过不断将查找区间减半来定位目标元素。

    构建步骤

    折半查找判定树的构建方法：

    1. 取 \(\text{mid} = \frac{1+n}{2}\) 作为根节点
    2. 左子树的根取 \(\frac{1+\text{mid}-1}{2}\)，右子树的根取 \(\frac{\text{mid}+1+n}{2}\)
    3. 如此递归构建整棵折半查找判定树

    平均查找长度 ASL

    成功 ASL
    待查找节点在第 \(h\) 层时需比较 \(h\) 次，将所有节点的比较次数加权求和即可：
    \[\text{ASL}_{\text{成功}} = \sum_{i=1}^{n} \frac{l_i}{n}\]

    其中 \(l_i\) 为第 \(i\) 个节点所在的层数。

    折半查找的效率

    折半查找的时间复杂度为 \(O(\log n)\)，远优于顺序查找的 \(O(n)\)。但其前提是表必须有序且采用顺序存储（链表无法高效实现折半查找）。

    二叉排序树

    二叉排序树（BST, Binary Sort Tree）是一种动态查找表结构，满足以下性质：

    • 左子树上所有节点的关键字 < 根节点的关键字
    • 右子树上所有节点的关键字 > 根节点的关键字
    • 左、右子树也分别是二叉排序树

    构建步骤

    1. 给定序列，第一个节点作为根节点
    2. 对后续每个元素：若比当前节点小，放入左子树；若比当前节点大，放入右子树
    3. 重复直至所有元素插入完毕

    删除节点调整

    删除节点 p 时分三种情况：

    叶子节点
    修改双亲指针即可，直接删除。
    仅有左（右）孩子
    用 p 的左（右）孩子指针代替 p 的位置，即让 p 的子树直接挂到 p 的双亲下面。
    有两个孩子
    用 p 的中序前驱或后继代替 p，即用左子树中最右节点或右子树中最左节点替换 p，然后删除该替换节点。

    双孩子节点的删除

    当 p 有两个孩子时，不能直接删除，必须找到一个合适的替代节点来保持 BST 性质。中序后继（右子树最左节点）或中序前驱（左子树最右节点）是唯一合法的替代选择。

    平衡二叉树

    平衡二叉树（AVL Tree）是在 BST 基础上增加平衡约束：任一节点的左右子树深度之差（平衡因子）不超过 1。

    最小不平衡子树

    从插入位置自下往上，第一个出现左右子树深度之差 \(> 1\) 的节点所构成的子树，称为最小不平衡子树。调整操作只需针对该子树进行。

    LL 型调整

    新插入节点在最小不平衡子树的左孩子的左子树上。

    调整方法：左孩子向右上旋转（单旋）。

    RR 型调整

    新插入节点在最小不平衡子树的右孩子的右子树上。

    调整方法：右孩子向左上旋转（单旋），与 LL 型刚好相反。

    LR 型调整

    新插入节点在最小不平衡子树的左孩子的右子树上。

    调整方法：左孩子的右子树先左上旋，再右上旋（双旋）。

    RL 型调整

    新插入节点在最小不平衡子树的右孩子的左子树上。

    调整方法：右孩子的左子树先右上旋，再左上旋（双旋），与 LR 型刚好相反。

    四种调整类型总结
    类型 插入位置 调整方法
    LL 左孩子的左子树 左孩子右上旋（单旋）
    RR 右孩子的右子树 右孩子左上旋（单旋）
    LR 左孩子的右子树 先左上旋再右上旋（双旋）
    RL 右孩子的左子树 先右上旋再左上旋（双旋）

    B-树

    B-树是一种多叉平衡搜索树，专为磁盘等外部存储设计，通过降低树高度减少 I/O 次数。

    \(m\) 阶 B-树的定义

    对 \(m\) 阶（\(m\) 叉）B-树，要求：

    • 每个节点最多有 \(m\) 个分支、\(m-1\) 个元素
    • 根节点至少有 \(2\) 个分支、\(1\) 个元素
    • 非根非叶节点至少有 \(\lceil \frac{m}{2} \rceil\) 个分支、\(\lceil \frac{m}{2} \rceil - 1\) 个元素
    • 所有叶子节点在同一层（平衡）

    构建和插入

    1. 先查找到插入位置，进行插入
    2. 若未发生上溢（节点元素数 \(\leq m-1\)），无需调整
    3. 若发生上溢（节点元素数 \(> m-1\)），将第 \(\lceil \frac{m}{2} \rceil\) 个元素（中间元素）向上移动到父节点，左右两侧分裂为两个新节点
    4. 若父节点也因此上溢，继续向上分裂，直至不再上溢或根节点分裂（此时树高度增加一层）

    删除

    B-树的根节点可始终置于内存中；其余非叶节点放置在外存上，每节点可作为一个读取单位（页/块）。选取较大的阶次 \(m\)，降低树的高度，减少外存访问次数。

    B+树

    B+树是 B-树的变体，在数据库索引中广泛使用。其与 B-树的主要区别：

    • 所有关键字及其对应的数据记录都存储在叶子节点中
    • 非叶节点仅存储索引信息（子树中最大/最小关键字），用于引导查找
    • 叶子节点之间通过链表连接，支持高效的范围查询
    B-树 vs B+树
    特性 B-树 B+树
    数据存储位置 所有节点都可能存储数据 仅叶子节点存储数据
    非叶节点内容 关键字 + 数据 仅索引关键字
    叶子节点链接 无 链表连接
    范围查询 需要中序遍历 直接沿链表扫描
