    输入输出系统

    I/O 端口与编址方式

    CPU 直接访问的寄存器称为 I/O 端口，CPU 通过 I/O 端口与外设连接，端口分为数据口、状态口和控制口。根据编址方式，分为两种：

    统一编址方式（存储器映射）
    主存和 I/O 端口共用地址空间。优点是不需要单独的 I/O 指令系统。
    独立编址方式（I/O 映射）
    I/O 端口有独立的内存空间。例如 x86 CPU 即采用此方式。

    I/O 接口与外设间的数据传送

    数据传送不仅涉及 CPU 与 I/O 端口之间，还涉及 I/O 接口与外设之间。接口与外设间的传送方式有：

    无条件传送
    适用于速度极慢或简单的外围设备（如机械开关），直接用数据线连接接口和外设，接口仅用于寻址和数据缓冲。
    应答方式（异步传送）
    适用于慢速或中速设备，或操作时间间隔不固定的设备（如键盘）。数据传送线之外还有信号线传递控制信息。
    同步传送方式
    适用于高速设备且操作时间间隔均匀的设备。接口以某一确定的时钟速率和外设交换信息，一旦确认同步，数据交换靠时钟脉冲控制进行。

    CPU 与外设间的数据传送方式

    无条件传送方式

    CPU 认为外设始终处于就绪状态，直接通过数据口和外设间传送数据，不需要控制口和状态口。

    局限

    可能出现丢失数据、覆盖数据或重复输入的情况，仅适用于极简单的场景。

    程序查询方式

    CPU 通过查询外设的状态决定何时进行输入和输出。对于多台外设，CPU 轮流按顺序查询每个外设的状态（轮询）。

    主要缺点

    CPU 需要不断查询并等待慢速设备，CPU 和外设无法并行工作，效率低。

    程序中断方式

    当外设需要 CPU 服务时，"主动"通过接口向 CPU 发出中断请求，CPU 在当前指令执行完后暂停主程序，转去执行中断服务程序，完毕后返回主程序。但这种方式需要保护现场等操作，适用于随机出现的服务；若中断频率高则容易出现阻塞。

    DMA 方式

    通过硬件控制在主存与 I/O 设备间直接通过 DMA（Direct Memory Access）通道进行数据传送，无需 CPU 干预，而是在 DMA 控制器下完成，速度快，能满足高速 I/O 设备的传送要求。

    通道方式

    通道将 DMA 进一步分为不同通道，分别完成与不同 I/O 设备的交互。通道是一种简单处理器，有专门的指令和程序负责数据输入输出的控制和管理；CPU 将"传输控制"功能下放给通道后，只负责"数据处理"功能。

    中断系统

    中断的基本概念

    中断系统
    计算机中实现中断功能的软硬件总称，包括 CPU 中的中断机构、系统中的中断控制器和中断服务程序（软件）。
    中断源
    能向 CPU 发出中断请求的部件或事件。键盘、打印机、磁盘磁带、电源掉电、设备故障、运算溢出、数据格式非法、校验错、调试断点等都属于中断源。

    中断处理流程

    中断周期的操作由硬件自动完成，也称为执行一条"中断隐指令"，但其并非软件层面上的指令。完整流程如下：

    1. 当前指令执行完毕后进入公操作阶段，CPU 检查有无中断请求；若有，则进入中断周期，响应中断。
    2. 中断周期：
      1. 关中断——禁止系统响应新的中断请求；
      2. 找出中断源，保存 PC；
      3. 转移至中断服务程序。
    3. 中断服务程序执行流程：
      1. 保护现场；
      2. 中断事件处理；
      3. 恢复现场；
      4. 开中断；
      5. 中断返回。
    注意

    中断不存在中断结束信号！

    中断源识别

    1. 使用中断控制器，识别哪个设备发出的中断；
    2. 单级中断方式下，使用串行排队链电路实现公共请求线的中断源判优识别。

    中断服务程序入口地址获取

    查询中断
    预先规定中断服务程序的入口地址。
    向量中断
    不同中断源发出的中断请求有不同的中断向量号，通过查询中断向量表，获取对应中断服务程序的入口地址（即中断向量）。

    中断标志寄存器

    外设接口和 CPU 中各有决定是否发起/响应中断请求的机构：

    位置 标志 含义
    接口中 RD 准备就绪
    接口中 EI 允许中断
    接口中 BS 忙
    CPU 中 IM 中断屏蔽（高有效）
    CPU 中 IR 中断请求（高有效）

    当 EI = 1 且 IM = 0 时，CPU 响应中断请求。

    单级中断与多级中断

    单级中断
    所有中断源都属于同一级，离 CPU 更近的中断源具有更高的优先级。
    多级中断
    优先级高的中断可以打断优先级低的中断程序，以多级嵌套方式工作。有 \(n\) 级中断则 CPU 中有 \(n\) 个 IM 和 IR。若某级中断被响应，则将本级和低于本级的 IM 置 1，屏蔽本级和低于本级的中断请求，但允许更高级的中断。采用独立请求方式 + 链式查询方式相结合确定中断级和中断源。使用堆栈保护现场（包括 IM）。

    DMA 方式

    DMA 传送过程

    DMA 传送分为四个阶段：

    1. 申请阶段（DMA 控制器 → CPU）：DMA 控制器收到传送请求后，向 CPU 发出总线请求信号，申请占用总线。
    2. 响应阶段（CPU → DMA 控制器）：CPU 响应请求，释放总线（将三总线变为高阻），回送总线应答信号。
    3. 数据传送阶段（外设 ↔ 主存）：DMA 控制器占用总线，向存储器和外设发出读/写控制信号完成数据传送，并修改地址计数器和字计数器。
    4. 传送结束阶段（DMA 控制器 → CPU）：规定字数传送完成后，DMA 控制器以中断方式或状态位方式向 CPU 报告操作结束，释放总线，CPU 重新占用总线。

    DMA 的 I/O 操作传送过程

    传送一个数据块分为三个阶段：

    1. 预处理：CPU 对 DMA 控制器进行初始化，设置传送参数，准备内存缓冲区数据。
    2. 数据传送：DMA 控制器控制外设与内存缓冲区进行数据交换。
    3. 后处理：对内存缓冲区进行处理（取走缓冲区数据或填入新数据，因为可能分多次传输）。

    DMA 的三种传送方式

    成组传送方式（停止 CPU 访存）
    CPU 响应 DMA 请求让出总线后，DMA 控制器将一组数据传送完毕再将总线还给 CPU。控制简单，适用于数据传输率很高的设备；缺点是 DMA 传送过程中 CPU 无法访存处理紧急事件。
    周期窃取（挪用）方式
    DMA 控制器与主存间传送一个数据，占用/窃取一个 CPU 周期。缺点是总线申请和归还存在过多时间开销。
    DMA 与 CPU 交替访存方式（透明 DMA）
    不需要总线申请和归还，总线使用权在一个 CPU 周期内分为 C1 和 C2 两个时间片，CPU 和 DMA 分时使用。

    DMA 控制器的基本组成

    DMA 控制器的主要部件：

    内存地址计数器
    初始指向内存缓冲区首地址，每传送一次自动加 1。
    字计数器
    传送数据块长度计数，每传送一次自动减 1。
    数据缓冲寄存器
    暂存每次传送的数据。
    控制/状态逻辑
    完成传送控制。
    中断机构
    当字计数器溢出时，表示传送结束，中断机构向 CPU 发出传送结束请求。

    选择型与多路型 DMA 控制器

    选择型 DMA 控制器
    某一段时间内只能为一个设备服务，共用硬件。
    多路型 DMA 控制器
    DMAC 能同时为多个慢速设备提供服务，有多套硬件，各设备间能以字节交叉方式进行数据传送。

    通道方式

    概述

    通道方式将 DMA 进一步分为不同通道，分别完成与不同 I/O 设备的交互：

    • 一个主机可以连接多个通道；
    • 一个通道可以连接多个 I/O 设备；
    • 通道是一种简单处理器，有专门的指令和程序负责数据输入输出的控制和管理；
    • CPU 将"传输控制"功能下放给通道后，只负责"数据处理"功能；
    • 通道与 CPU 分时使用主存，实现 CPU 内部处理与 I/O 设备的并行工作。

    基本工作流程

    1. CPU 向通道控制器发送命令，启动通道；
    2. 通道控制器执行内存中的通道程序进行 I/O 操作；
    3. 执行完通道程序最后一条指令后，通道控制器向 I/O 设备发出结束命令，同时向 CPU 发出中断请求信号，并将通道状态写入主存；
    4. CPU 收到中断请求信号后，执行 I/O 中断服务程序，对通道进行结束处理。

    通道控制器的组成

    通道地址字寄存器
    相当于 PC，用于存放通道程序的地址。
    通道指令字寄存器
    存放当前执行的通道指令。
    设备地址寄存器
    存放当前操作的设备地址。
    通道状态字寄存器
    存放通道和设备的状态信息。

    通道类型

    选择通道（Selector Channel）
    又称高速通道。物理上可连接多个外设，但同一时间只能选择一台外设独占整个通道，以成组方式传送数据块，逻辑上只连接一台设备。效率高，适合快速设备。
    字节多路通道
    简单的多路通道，分时处理，适用于低中速设备。包含多个子通道，一段时间内能交替执行多个设备的通道程序。
    数组多路通道
    多个设备以数据块为单位交叉使用通道，效率高但控制复杂。一段时间内轮流执行多台设备的通道程序。

    通道 vs. DMA

    比较项 DMA 方式 通道方式
    硬件复杂度 较复杂 较复杂
    I/O 操作实现 由硬件完成 由通道程序完成
    初始化操作 通过 CPU 完成 通过通道程序完成
    连接设备数 较少 能连接更多外部设备

    中断 vs. DMA 综合对比

    比较项 程序中断方式 DMA 方式
    保护现场 需要保护和恢复现场 无需保护现场
    CPU 参与度 高，CPU 要处理中断并逐个字节读写 低，仅在预处理和后处理阶段需要 CPU
    传送方式 主要靠中断服务程序 靠 DMA 控制器硬件进行传送
    响应请求时机 每条指令执行完毕后 每个总线周期结束
    效率 中，适合低速/间歇设备 高，适合高速设备的成组数据传送
    传输粒度 一次中断传送一个或少量字节 一次 DMA 可传送多个字节（甚至整个块）
    中断频率 多次中断 一次中断（DMA 传输完毕后通知）
    典型应用 键盘、鼠标、串口等 硬盘、显卡、声卡、网卡等高速设备
    CPU 空闲度 占用高 占用低，可并发运行其他任务
    优先级 低于 DMA 请求 高于中断请求
