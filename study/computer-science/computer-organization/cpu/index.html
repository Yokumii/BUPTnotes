    中央处理器

    处理器功能

    1. 指令控制：控制程序严格按照规定顺序执行
    2. 操作控制：处理器根据从内存取出的每条指令产生相应的操作信号，送往相应的部件，控制这些部件按指令的要求进行动作
    3. 时间控制：对各种操作实施时间进行控制
    4. 数据加工
    5. 中断处理

    CPU 模型及其组成

    CPU 由控制器和运算器两大部分组成：

    控制器

    从指令 cache 中读取当前指令，并指出下一条指令在指令 cache 中的位置；对指令进行译码，产生操作控制信号；指挥并控制 CPU、内存和 IO 设备之间的数据流动

    • 程序计数器 PC：保存将要执行的下一条指令的地址
    • 指令寄存器 IR：保存当前正在执行的一条指令；保存的操作码字段就是指令译码器的输入
    • 指令译码器
    • 操作控制器 OC：根据指令的操作码和时序信号，产生各种操作的控制信号。根据设计方法不同可分为：
      • 硬布线控制器：采用时序逻辑
      • 微程序控制器：采用存储逻辑
    • 时序产生器：对各种操作信号进行执行时间先后顺序控制
    运算器

    对数据进行加工处理，是执行部件，执行所有算术运算、逻辑运算和测试运算

    • 算术逻辑单元 ALU
    • 累加寄存器
    • 数据缓冲寄存器 DR：暂存从数据 cache 中读出的或来自外部接口的一个数据字，或 ALU 的运算结果；它是 ALU 运算结果和通用寄存器组之间的缓冲；用来补偿 CPU、内存和外设在操作速度上的差异
    • 程序状态字寄存器 PSWR：保存运算结果标志（进位标志、零标志、溢出标志、负标志）；保存中断和系统工作状态等信息

    其他主要寄存器

    • 地址寄存器 AR：存放处理器当前访问的数据 cache 中数据单元的地址
    • 通用寄存器 R0 ~ R3：暂存 ALU 的运算结果
    数据通路
    寄存器之间、寄存器与 ALU 之间传送数据通路的总称

    CPU 如何区分指令和数据？

    控制器根据指令周期的不同阶段区分指令和数据。

    指令周期

    程序的执行过程

    在冯诺依曼结构（存储程序式计算机）中，程序运行之前需要将程序和数据均放到内存中，具体执行顺序如下：

    1. 将程序首地址送入程序计数器 PC
    2. 从内存（cache）中取出该指令并执行
    3. 形成下一条待执行指令的地址，保存到 PC 中
    4. 自动连续执行指令，直至最后一条指令

    即一个取指令 + 执行指令的过程。

    基本概念

    指令周期
    取指令 + 分析指令 + 执行指令所需的总时间。由于各种指令的执行时间不同，各种指令的指令周期也不相同。一个指令周期包含若干个 CPU 周期
    CPU 周期 / 机器周期
    一个机器周期包含若干个时钟周期
    时钟周期
    处理操作的基本单位，也称节拍脉冲

    指令周期包括以下阶段：

    1. 取指周期：从主存取出指令，更新 PC
    2. 间址周期（如果有）：计算操作数的有效地址
    3. 执行周期：取出操作数，执行运算，存操作数
    4. 中断周期：检查是否有中断请求

    指令的执行步骤

    MOV 指令

    MOV 指令是数据传送指令，属于 RR 型指令。假设指令为 MOV R1 R0：

    1. 取指令（1 个 CPU 周期）
      • 从内存（cache）中取出当前 MOV 指令
      • PC += 1，为取下一条指令作准备
      • 指令译码/测试
    2. 执行指令（1 个 CPU 周期）
      • 读取寄存器 R0 中的数
      • 通过 ALU 以及三态门读到数据总线 DBUS 上
      • 将取出来的数写入数据缓冲寄存器 DR
      • 将 DR 中的数写入寄存器 R1

    MOV 指令周期 = 2 个 CPU 周期

    LAD 指令

    LAD 指令从内存加载数据到寄存器，属于 RS 型指令。假设指令为 LAD R1 A：

    1. 取指令（1 个 CPU 周期）
      • 从内存（cache）中取出当前 LAD 指令
      • PC += 1
      • 指令译码/测试
    2. 执行指令
      • 送操作数地址（1 个 CPU 周期）：将操作数的直接地址 A 装入地址寄存器 AR
      • 取出操作数，装入通用寄存器（1 个 CPU 周期）：从数据存储器中读出 A 地址上的数，发送至数据总线；写入 DR；写入 R1

    LAD 指令周期 = 3 个 CPU 周期

    ADD 指令

    ADD 指令属于 RR 型指令。假设指令为 ADD R1 R2：

    1. 取指令（1 个 CPU 周期）
      • 从内存（cache）中取出当前 ADD 指令
      • PC += 1
      • 指令译码/测试
    2. 执行指令（1 个 CPU 周期）
      • 读取寄存器 R1 和 R2 上的数
      • 通过 ALU 执行加法运算，结果通过三态门发送至数据总线
      • 将运算结果暂存至 DR
      • 将 DR 暂存的运算结果写入寄存器 R1

    ADD 指令周期 = 2 个 CPU 周期

    STO 指令

    STO 指令将寄存器中的数写入内存，属于 RS 型指令。假设指令为 STO R2(R3)：

    1. 取指令（1 个 CPU 周期）
      • 从内存（cache）中取出当前 STO 指令
      • PC += 1
      • 指令译码/测试
    2. 执行指令
      • 送操作数地址（1 个 CPU 周期）：从寄存器 R3 中取出操作数的直接地址，装入 AR
      • 送操作数地址，执行写操作（1 个 CPU 周期）：从 R2 中的数读出，发送到数据总线上；发出写命令，将数据总线上的数写入 AR 对应的地址单元

    STO 指令周期 = 3 个 CPU 周期

    JMP 指令

    JMP 指令是无条件转移指令。假设指令为 JMP A：

    1. 取指令（1 个 CPU 周期）
      • 从内存（cache）中取出当前 JMP 指令
      • PC += 1
      • 指令译码/测试
    2. 执行指令（1 个 CPU 周期）
      • 将转移地址 A 送往程序计数器 PC

    JMP 指令周期 = 2 个 CPU 周期

    执行步骤总结

    1. 读取指令（1 次访存）——公共操作
    2. 分析指令
    3. 执行指令：不同指令操作步骤不同
    4. 检查有无中断请求——公共操作
    公操作

    公操作是一条指令执行完毕后，CPU 所进行的公共操作，如中断处理等。

    时序产生器和控制方式

    控制器分类与时序体制

    硬布线控制器
    时序信号一般采用 主状态周期 — 节拍电位 — 节拍脉冲 的三级体制，节拍电位 = CPU 周期时间
    微程序控制器

    时序信号较简单，采用 节拍电位 — 节拍脉冲 的二级体制

    其组成包括：时钟源、环形脉冲发生器、节拍脉冲和读写时序译码、启停控制逻辑

    控制方式

    同步控制
    执行各指令所需的机器周期数和时钟周期数固定不变
    异步控制
    每条指令和操作控制信号按需占用时间；每条指令的指令周期可以由多个不等长的机器周期构成
    联合控制
    同步与异步方式的结合

    微程序控制器

    与硬布线控制器对比

    微程序控制器按照软件设计的思想设计硬件，相较于硬布线控制器，具有规整性、灵活性、可维护性等优点。

    基本概念

    微命令
    控制部件通过控制线向执行部件发出的各种控制信号（即控制信号）
    微操作

    执行部件接收到微命令后执行的特定操作。微命令和微操作是最小单位，两者一一对应

    • 相容性操作：同时在一个 CPU 周期内可以并行的操作
    • 相斥性操作：不能同时在一个 CPU 周期内并行的操作
    反馈信息
    执行部件使用反馈线向控制部件报告操作情况，控制部件根据反馈信息发出新的微命令
    微指令

    在一个 CPU 周期内，实现某个操作功能的一组微命令构成了微指令。用一条微指令对应一个机器指令的一个执行步骤

    微指令需要提供： - 执行该步骤所需的控制信号 - 提供下一条需要执行的微指令的地址

    微周期
    从控制存储器中取出一条微指令并执行所需的全部时间，通常为 1 个时钟周期
    微程序
    一条机器指令对应一段微程序，微程序即实现一条机器指令所需的多条微指令序列
    层次对应关系
    • 程序 — 微程序，指令 — 微程序 — 多条微指令 — 若干微命令和微操作
    • 指令 — 指令周期 — 多个微周期 — 多个时钟周期

    注意区分程序与微程序、机器指令与微指令、地址与微地址的对应关系。前者与主存有关，而后者与控制存储器有关：

    微指令的基本格式

    微指令包括操作控制字段和顺序控制字段：

    • 操作控制字段用于发出控制信号，每一位对应一个微命令
    • 顺序控制字段用于产生下一条微指令的地址

    微程序控制器原理

    控制存储器
    用来存放全部指令系统的微程序的只读存储器。从控制存储器中读出一条微指令并执行的时间总和称为微指令周期
    微指令寄存器

    用于存放由控制存储器读出的一条微指令

    • 微地址寄存器：用于决定将要访问的下一条微指令的地址
    地址转移逻辑
    正常情况下，由微指令的顺序控制字段直接给出下一条微指令的地址并存放在微地址寄存器中；当微程序出现分支，则需要根据状态条件、指令寄存器 IR 等计算地址转移

    基本执行过程如下：

    1. 执行"取指"指令，即取出指令，这是所有机器指令的共用微指令，一般存放在地址 0000 处；所有机器指令的最后一条微指令的直接地址都指向 0000，用于取下一条指令
    2. 进入 P1 测试（操作码测试），产生对应的微程序入口指令，送入微地址寄存器
    3. 该条微指令执行完毕后，进入 P2 测试，用于计算下一条微指令的地址，读取微指令，重复上述操作
    4. 当微程序对应的所有微指令均被执行完后，返回到 0000 处，即取指微指令，用于执行下一段微程序

    微命令编码

    1. 直接表示法：微指令的控制字段中每一位对应一个微命令（即控制信号）

      • 简单直观，无需译码
      • 缺点：操作控制部分过长

    2. 编码表示法：把一组相斥的微命令合并成一个小组，对应一个字段，通过小组译码器对微命令信号进行译码，译码输出作为控制信号。\(n\) 位二进制译码后可以表示 \(2^{n} - 1\) 个微命令

      为什么是 \(2^n - 1\) 而不是 \(2^n\)？

      编码表示法中用"全 0 码不表示任何有效微命令"，即全 0 表示无操作，所以剩下 \(2^n - 1\) 个微命令才是有效的。

      • 需要译码，但能有效缩短微指令长度

    3. 混合表示法：更灵活，结合直接表示法和编码表示法

    产生后继地址的方法

    计数器方式

    与程序计数器 PC 类似：

    • 顺序执行微指令时，下一条微指令的地址通过当前微地址 + 一个增量产生
    • 非顺序执行时需要通过一定的转移方式产生下一条微地址

    优缺点

    • 优点：需要的顺序控制字段少
    • 缺点：多路并行转移功能弱，速度慢、灵活性差
    多路转移方式

    程序运行时：

    • 不产生分支时：后继微地址直接由本条微地址的顺序控制字段给出
    • 产生分支时：根据本条微地址的顺序控制字段的 P 字段（即判别测试位）和状态条件位来从若干"候选"微地址中选择

    状态条件有 \(n\) 位 \(\Rightarrow\) 可以实现 \(2^n\) 路转移（即对应 \(2^n\) 个微程序入口） \(\Rightarrow\) 涉及微地址寄存器的 \(n\) 位（\(n\) 位状态条件直接存入微地址寄存器，微地址寄存器的高位相当于"基地址"）

    优缺点

    • 优点：多路并行转移功能强，速度快，更灵活
    • 缺点：多路转移需要复杂的组合逻辑

    微指令格式

    水平型微指令

    一次能定义并执行多个并行操作的微命令的微指令。包含控制字段、判别测试字段（P 字段）、下地址字段

    垂直型微指令

    类似机器指令，通过设置微操作码字段规定微指令的功能，长度较短，但一条微指令只有 1 ~ 2 个微操作命令，实现一条机器指令对应的微程序需要的垂直型微指令更多

    特性 水平型微指令 垂直型微指令
    微指令长度 较长（几十位以上） 较短（一般十几位）
    控制信号表达方式 每一位直接对应一个控制信号（位控） 每一字段经过译码，控制一类信号，类似机器指令
    并行性 高（多个控制信号可同时激活） 低（同类操作需顺序进行）
    执行时间 短 慢
    灵活性 强（可并行调度） 弱（调度受限）
    容易程度 用户难以掌握 用户容易掌握

    硬布线控制器

    硬布线控制器，又称组合逻辑控制器，RISC（精简指令集）计算机通常采用这种方式。

    从上图可见，控制信号形成的逻辑网络主要有以下三个输入来源：

    1. 指令寄存器 IR 通过指令译码器的输出
    2. 执行部件的反馈状态信息
    3. 时序产生器参数的时序信号，包括节拍电位和节拍脉冲

    特点包括：

    • 形成控制信号的传输延迟较少，能提高系统的执行速度
    • 时序控制信号较为复杂
    • 设计变更困难，即指令的修改和扩展困难（因为逻辑电路设计和修改困难）
    • 硬布线控制的速度较快（因为不需要像微程序控制器一样访问控制存储器，主要取决于电路延迟）

    硬布线控制器 vs. 微程序控制器

    特性 硬布线控制器 微程序控制器
    控制信号产生方式 用组合逻辑电路（如译码器、状态机）直接生成 用微指令存储在控制存储器（Control Memory）中
    控制器本质 固定逻辑电路 存储程序 + 微程序解释器
    结构复杂度 高（电路复杂） 低（程序驱动）
    速度 快（信号由逻辑门直接产生） 较慢（每条指令需读微指令）
    修改灵活性 差（要重新布线/改电路） 好（只需改微程序）
    适用范围 高速处理器、简单控制器 多功能、通用处理器
    设计成本 一次性高，不易修改和扩展 长期维护简单
    例子 RISC 处理器（如 MIPS 硬件控制） CISC 处理器（如 Intel 早期 x86）

    流水线 CPU

    流水线 CPU 的结构

    系统组成

    • 指令部件：取指令、指令译码、计算操作数地址、取操作数
    • 指令队列：FIFO（先进先出队列），存放取出并译码后的指令和操作数
    • 执行部件：算术逻辑运算流水线

    指令执行的分解

    一条指令的处理过程一般可以分为如下过程段：

    1. IF 取指（Instruction Fetch）：从存储器取出指令
    2. ID 译码（Instruction Decode）：指令译码，读寄存器
    3. EX 执行（Execution）：执行指令或计算地址
    4. MEM 访存（Memory）：访问存储器
    5. WB 写回（Write Back）：将结果写回寄存器

    时空图对比

    非流水线时空图

    一条指令的四个子过程全部执行完才能执行下一条。

    标量流水线时空图

    子过程在时间上可以重叠执行。

    超标量流水线

    具有 2 条以上指令流水线。

    流水线分类

    • 指令流水线：处理指令步骤的并行
    • 算术流水线：运算操作步骤的并行
    • 处理机流水线 / 宏流水线：程序步骤的并行

    流水线硬件的基本结构

    每个指令周期包含多个子过程，每个子过程称为过程段，用 \(S\) 表示；过程段之间的是缓冲寄存器/锁存器（Latch），用于临时保存流水线各阶段产生的数据，用 \(L\) 表示。

    时钟周期和处理频率计算

    设阶段 \(S_i\) 所需的时间为 \(\tau_i\)，缓冲寄存器的延时为 \(\tau_l\)，则线性流水线的时钟周期定义为：

    \[ \tau = \max\{\tau_i\} + \tau_l \]

    流水线处理的频率为：

    \[ f = \frac{1}{\tau} \]

    线性流水线的三个阶段

    1. 装满 Filling：流水线开始运行，还没装满所有处理段；共需要 \(T_0 = k\Delta t_0\)，即需要 \(k\) 个指令周期装满
    2. 稳定流水 Steady：流水线每个时钟周期都有一个任务被完成，最高效；无论有多少个过程段，每个时钟周期均能输出一个任务
    3. 排空 Draining：当最后一个任务进入流水线后，流水线还需运行 \((k-1)\Delta t_0\) 时间完成剩余工作

    流水线的性能指标

    使用 \(k\) 级流水线完成 \(n\) 个任务，共需要：

    \[ T_k = k\Delta t_0 + (n - 1)\Delta t_0 = (k + n - 1)\tau \]

    而不使用流水线，需要 \(T_0 = n \cdot k \cdot \tau\)。

    加速比

    流水线工作相当于等效的非流水线顺序串行工作方式速度提高的比值：

    \[S = \frac{T_0}{T_k} = \frac{n \cdot k \cdot \tau}{(k + n - 1)\tau} = \frac{n \cdot k}{k + n - 1}\]

    当 \(n \gg k\) 时，最大加速比为 \(k\)。

    吞吐率（Throughput Rate）

    指令执行的速度：

    \[TP = \frac{n}{(k + n - 1)\tau}\]

    当 \(n \rightarrow \infty\) 时，最大吞吐率：

    \[TP_{\max} = \lim_{n \to \infty} \frac{n}{(k + n - 1)\tau} = \frac{1}{\tau}\]

    流水线的特点

    • 流水线不能加速单条指令的执行过程
    • 实现多条指令重叠执行
    • 潜在加速比 = 流水线级数（注意实际工作过程中无法达到）
    • 流水线的速率受限于最慢的过程段
    • 如果过程段的执行时间不一致，加速比就会降低

    流水线的冒险

    结构冒险 / 资源相关

    同一时钟周期下，指令同时试图争用同一资源。比如取指和访存由于都需要访问存储器，可能会造成资源冲突。最常见的就是访存冲突。

    消除结构冒险的方法包括：

    1. 暂停其中一条指令的时钟，停顿一拍后再启动
    2. 将数据和指令保存在不同的存储器中

    数据冒险

    一条指令的执行依赖于更早的一条还在流水线中指令的执行结果。

    第二条指令的源操作数之一依赖于第一条指令的运算结果。运算结果需要在写回寄存器时才能生效，而取操作数是在译码阶段就需要进行，同时执行会导致取出错误或无效的内容。按照上面的例子需要插入 3 个额外的时钟周期（即 Bubble）。

    数据冒险主要有以下几种：

    1. 写后读 RAW（Read After Write）
    2. 读后写 WAR（Write after Read），又称为反相关
    3. 写后写 WAW（Write after Write），又称输出相关

    消除数据冒险的方法：

    前推 Forwarding / 旁路 Bypassing

    即额外连接数据通路，使之直接使用计算出的结果，而不是等待结果被写入寄存器

    控制冒险

    由条件转移指令引起，即下一条指令依赖当前分支指令的结果。但按照流水线工作方式，取指是连续进行的，条件转移导致流水线无法始终取到正确的指令，需要等待分支指令的结果出来才能取指，导致流水线阻塞。

    解决方法是分支预测：

    静态分支预测
    • 简单分支预测：直接预测分支发生 or 不发生
    • 复杂分支预测：编译器在编译时进行分支，对指令进行重排从而消除控制冒险；可以把一条与分支无关、原本在跳转后执行但可以提前的指令，重排到延迟槽中，重排后的代码并不会影响程序的正确性

    动态分支预测

    通过历史行为进行预测，需要硬件支持。处理器需要维护一张分支历史表 BHT

    什么是指令流水线，优势是什么？

    指令流水线是把指令分解为若干子过程，通过将每个子过程与其他子过程并行执行，来提高计算机的吞吐率的技术。采用流水线技术只需增加少量硬件就能把计算机的运算速度提高几倍，因此成为计算机中普遍使用的一种并行处理技术，通过在同一个时间段使用各功能部件，使得利用率明显提高。

    RISC vs. CISC

    RISC 要素

    • 指令数量少，简单
    • CPU 具有大量的通用寄存器
    • 强调对流水线的优化

    对比

    特性 CISC RISC
    指令数量 多、复杂（上百种） 少、简单（几十种）
    指令长度 不固定，指令格式复杂 固定长度
    执行时间 每条指令执行时间不确定 每条指令一般在一个机器周期内完成
    指令使用频度 差异很大 差异不大，都比较常用
    寻址方式 多种寻址方式 寻址方式较少，简单
    操作对象 内存和寄存器都可操作，可以访问存储器的指令不受限制 只操作寄存器，访问内存需专门指令（Load/Store）
    通用寄存器数量 通用寄存器数量较少 通用寄存器数量多，减少访存次数
    控制器 微程序控制方式，指令使用频度差异大 硬布线控制逻辑，控制器简单，Cache 容量大
    编译 难以用优化编译生成高效的目标代码 编译器技术优化
    性能优化方式 各种指令的执行时间相差很大，不利于流水线处理 大部分指令都能在一个机器周期内完成，采用流水线技术

    注意

    RISC 由于指令结构精简，每条指令功能简单，往往需要通过组合实现复杂功能，编译器的设计难度和编程难度增大，兼容性差于 CISC。
