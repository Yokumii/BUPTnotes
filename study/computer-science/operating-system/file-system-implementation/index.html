    文件系统实现

    文件系统结构

    文件系统采用分层架构，自顶向下依次为：

    层次 名称 职责
    1 Application Programs 应用程序通过系统调用请求文件操作
    2 Logical File System 管理元数据与目录结构，通过 FCB 将文件名映射到 inode，再定位文件位置
    3 File-Organization Module 逻辑块到物理块的映射，管理磁盘空间分配
    4 Basic File System 块级 I/O 调度与缓存管理
    5 I/O Control 硬件驱动程序，向设备控制器发送命令

    完整执行流程

    以应用程序调用 read() 为例，数据从磁盘到用户缓冲区的完整路径：

    1. 应用程序调用 read()，触发系统调用
    2. Logical File System：根据文件描述符（fd）查找 inode，检查访问权限
    3. File-Organization Module：将逻辑块号转换为物理块号
    4. Basic File System：向磁盘请求对应物理块，检查并更新缓存
    5. I/O Control：驱动程序向磁盘控制器发送读取命令
    6. 设备：磁盘执行物理读取
    7. 数据逐层返回，最终写入用户缓冲区

    磁盘结构

    磁盘上的结构

    结构 粒度 说明 示例
    Boot Control Block 每卷 位于卷的第一个磁盘块，包含启动信息 UFS Boot Block、NTFS Partition Boot Sector
    Volume/Partition Control Block 每卷 描述文件系统整体信息：总块数、块大小、空闲块数等 UFS Superblock、NTFS MFT
    Directory Structure 每个文件系统 文件名到 inode/MFT 记录的映射 目录项
    FCB（File Control Block） 每个文件 文件元数据：权限、时间戳、大小、数据块位置 UFS inode、NTFS MFT 记录

    内存中的结构

    文件系统运行时，需要在内存中维护以下结构以加速访问：

    • Mount Table：记录已挂载的文件系统信息
    • Directory Cache：目录项缓存，加速路径解析
    • System-wide Open-file Table：系统全局打开文件表，每个打开文件对应一个条目，包含 FCB 副本等信息
    • Per-process Open-file Table：每进程打开文件表，指向系统全局表中的对应条目
    • Buffers/Cache：磁盘块缓存，减少实际 I/O 次数

    文件分配方法

    连续分配

    文件占据一组连续的物理块。FCB 中记录文件的起始块号和长度。

    地址映射：对于流式文件，逻辑地址 \(L\) 对应的物理块号为：

    \[\text{物理块号} = \text{起始块号} + \left\lfloor \frac{L}{\text{块大小}} \right\rfloor\]

    对于记录式文件，计算方式类似，将记录号转换为逻辑地址后再做映射。

    优点
    支持随机访问，访问速度快（只需一次寻道）
    缺点
    产生外部碎片；难以找到足够大的连续空间；文件动态增长困难

    链接分配

    数据块可以分散在磁盘任意位置，每个数据块中存储指向下一个数据块的指针。FCB/inode 中存储起始块号（可选存储结束块号）。

    优点
    无外部碎片；空间利用灵活；文件可动态增长
    缺点
    不支持随机访问（必须从头遍历）；指针占用存储空间；指针损坏导致后续所有数据丢失
    FAT 改进

    文件分配表（FAT）将所有数据块的指针集中存放在一张表中，该表缓存在内存中。访问任意块时只需查表即可，避免了逐块读取指针的开销，实质上将链接分配的随机访问性能大幅提升。

    索引分配

    将文件所有数据块的指针集中存放在一个索引块中。FCB/inode 中存储索引块的地址。索引块本质上是一个数组：数组下标 = 逻辑块号，数组值 = 物理块号。

    优点
    支持随机访问；无外部碎片；文件可动态增长
    缺点
    小文件也需要额外的索引块开销；大文件单个索引块不够存放所有指针

    多级索引

    对于大文件，单个索引块不足以存放所有指针，此时可采用多级索引：一级索引块中存放二级索引块的地址，二级索引块中再存放数据块的地址。

    以 Linux ext2 文件系统的 inode 为例，它采用混合索引策略：

    • 直接地址指针（12 个）：直接指向数据块，适合小文件
    • 一次间接指针：指向一个索引块，索引块中存放数据块地址
    • 二次间接指针：指向一级索引块，一级索引块指向二级索引块，二级索引块中存放数据块地址
    • 三次间接指针：三级间接索引，支持极大文件
    索引级别与可寻址文件大小

    设块大小为 \(B\) 字节，每个指针占 \(P\) 字节，则每个索引块可存放 \(\frac{B}{P}\) 个指针。

    • 直接：\(12 \times B\) 字节
    • 一次间接：\(\frac{B}{P} \times B\) 字节
    • 二次间接：\(\left(\frac{B}{P}\right)^2 \times B\) 字节
    • 三次间接：\(\left(\frac{B}{P}\right)^3 \times B\) 字节

    空闲空间管理

    位图 / 位向量

    每个磁盘块对应 1 个 bit：0 表示空闲，1 表示已分配。

    优点
    容易找到连续的空闲空间；位图紧凑，可缓存在内存中
    缺点
    位图本身占用额外空间（磁盘块总数的 \(\frac{1}{8}\) 字节）
    位图空间计算

    设磁盘容量为 16 GB，块大小为 4 KB，则共有 \(\frac{16 \times 2^{30}}{4 \times 2^{10}} = 2^{22}\) 个块。位图需要 \(2^{22}\) bit \(= 2^{19}\) B \(= 512\) KB。

    链表

    将所有空闲块用链表串联起来，链表头指针存放在磁盘上的特殊位置，并缓存在内存中。

    优点
    无额外空间开销
    缺点
    遍历效率低；不易找到连续空闲空间

    分组

    在一个空闲块中存放 \(n\) 个空闲块地址，其中前 \(n-1\) 个直接指向空闲块，最后一个指向下一个分组块。

    优点
    可快速获取大量空闲块信息
    缺点
    不易找到连续空闲空间

    计数

    记录每个空闲区域的起始位置 + 连续空闲块数，类似于 (起始块号, 数量) 的列表。

    优点
    适合连续分配场景，可快速定位大块连续空闲空间
    缺点
    空闲空间频繁分配/释放时，列表项数量可能增多
