    文件系统接口

    文件属性

    文件是操作系统管理信息的基本单位，每个文件都有一组关联的属性：

    名称（Name）
    文件的人类可读标识符，用户通过名称引用文件
    标识符（Identifier）
    文件在系统内部的唯一标识，是非人类可读的标签（如 inode 号）
    类型（Type）
    文件的类型信息（如文本文件、二进制文件、目录等）
    位置（Location）
    指向文件所在磁盘块位置的指针
    大小（Size）
    文件的当前大小
    保护（Protection）
    文件的访问控制信息，决定哪些用户可以何种方式访问文件
    时间/日期/用户 ID
    文件的创建时间、最近修改时间、最近访问时间，以及文件所有者的用户 ID

    文件存储在目录结构中。目录条目由文件名和唯一标识符组成，系统通过唯一标识符在磁盘上定位文件的实际内容。

    文件操作

    操作系统为文件提供以下基本操作：

    • 创建（create）：在目录中为新文件分配空间并建立目录条目
    • 写（write）：向文件中写入数据，系统维护写指针指向当前写入位置
    • 读（read）：从文件中读取数据，系统维护读指针指向当前读取位置
    • 重定位（reposition）：移动文件指针到指定位置（即 seek 操作）
    • 删除（delete）：释放文件占用的空间，移除目录条目
    • 截断（truncate）：保留文件属性但删除文件内容，将文件大小归零

    操作的第一步

    几乎所有文件操作的第一步都是通过目录查找文件，获取文件的元数据和磁盘位置。

    打开文件表

    操作系统在内核中维护一张打开文件表（open-file table），记录所有当前打开的文件信息。

    打开与关闭

    打开（Open）
    查找目录条目 → 将文件信息复制到打开文件表 → 返回指向该表项的指针
    关闭（Close）
    将打开文件表中的条目移回磁盘，释放表项空间

    两级表结构

    打开文件表采用两级结构：

    系统级打开文件表
    系统全局唯一，包含所有进程打开的文件信息（如磁盘位置等）。当多个进程打开同一文件时，它们共享同一个系统级表项
    进程级打开文件表
    每个进程拥有一张，记录该进程打开的文件。进程级表项通过指针指向系统级表项，从而实现文件共享

    共享机制

    进程级打开文件表的条目指向系统级打开文件表的条目，这样多个进程可以共享同一个打开文件的信息，而无需重复存储。

    访问方法

    顺序访问

    顺序访问是最简单的访问方式，文件信息按顺序逐条处理。系统维护一个指针，每次读写后自动前进。

    顺序访问支持的命令：

    • read next：读取指针当前位置的记录，指针自动前进
    • write next：在指针当前位置写入记录，指针自动前进
    • reset：将指针重置到文件开头
    • rewrite：重写最近读取的记录（指针不前进）
    • 写入后不可再读取（write next 后不能 read next）

    直接访问

    直接访问（又称随机访问）允许按任意顺序访问文件中的块。每个块有一个相对块号 n（从 0 开始编号），程序可以直接指定要访问的块号。

    直接访问支持的命令：

    • read(n)：读取第 n 个块
    • write(n)：写入第 n 个块
    • position(n)：将指针移动到第 n 个块
    • read next / write next：从当前指针位置读写，指针自动前进
    • rewrite(n)：重写第 n 个块

    顺序访问 vs 直接访问

    顺序访问适用于顺序处理的场景（如文本编辑、磁带设备）；直接访问适用于需要快速定位的场景（如数据库查询、磁盘设备）。直接访问可以模拟顺序访问，反之则不行。

    目录结构

    目录是文件名到文件实体的映射集合，负责组织和管理文件。不同的目录结构在命名冲突、搜索效率和文件共享等方面各有优劣。

    单级目录

    所有文件存储在同一个目录中。

    • 优点：结构简单，实现容易
    • 缺点：
      • 文件名必须全局唯一，命名冲突严重
      • 搜索效率低（需遍历整个目录）
      • 无法按用户或类别分组

    两级目录

    系统分为主文件目录（MFD）和用户文件目录（UFD）两级。

    MFD（Master File Directory）
    系统中唯一的主目录，记录所有用户名及其对应的 UFD 指针
    UFD（User File Directory）
    每个用户拥有一个，记录该用户的文件信息
    • 优点：文件名只需在用户范围内唯一，解决了命名冲突问题
    • 缺点：用户之间相互隔离，无法方便地共享文件；访问文件需使用路径名

    树形结构目录

    目录组织为层次化的树形结构，每个目录可以包含文件和子目录。从根目录到目标文件的路径称为路径名。

    • 优点：层次清晰，支持按类别组织文件，搜索效率高
    • 缺点：树形结构中每个节点只能有一个父节点，因此不支持文件共享

    绝对路径与相对路径

    • 绝对路径：从根目录（/）开始的完整路径
    • 相对路径：从当前工作目录开始的路径

    无环图目录

    无环图目录在树形结构的基础上允许文件和子目录被多个目录共享，但不允许出现环（循环引用）。

    共享的实现方式有两种：

    链接（Link）
    在目录中创建一个指向已有文件的链接，该条目标记为链接类型。当被链接的文件被删除时，链接变为悬空链接（dangling link），系统需要检测并处理这种情况
    副本（Duplicate）
    将文件的完整信息复制到多个目录中。删除操作较复杂——当删除一个共享文件时，必须检查所有共享该文件的目录，确保只有在所有共享者都不再需要时才真正删除文件

    为什么不允许环

    如果目录图中存在环，遍历时可能陷入无限循环，且删除操作无法确定安全的顺序，因此无环图目录禁止环路。
